## Interfaces and measured identity

`collectProbe(ProbeOptions): Promise<ProbeObservation>` is one read/publication cycle. Its typed `HealthReader(signal): Promise<HealthRead>` and `PublicationPort.publish(observation, signal): Promise<Publication>` isolate concrete IO. Publication is `acknowledged` or `failed` with a bounded adapter-generated reason; it never means stored-backend acceptance. Request failures retain `success:false`, nullable actual revision/duration and an explicit reason. Invalid trusted config/source identity/wire shape/time throw. Expected failures are returned and the periodic runner continues.

`runProbe` defaults to 30-second start cadence, at most 20 seconds for each collection, sequential cycles. `signal` cancels active requests/SSH and interval sleep. The prior completed observation is exposed through `onCompleted`, and optionally `previous` at restart. `acceptance.assess(previous, signal): Promise<ObservationHealth>` runs concurrently with the next collection; `onAssessed` receives its result. Both promises are joined immediately, cancellation is shared, and prior assessment has its own finite race against the same deadline. Timeout/cancellation returns incomplete health with explicit unavailable deadline reasons. Unexpected assessment errors throw and cancel current collection. There is no concrete backend acceptance adapter here.

`createSshHealthReader()` uses fixed argv: `ssh -o BatchMode=yes -o ConnectTimeout=5 h2puni sudo -n docker inspect wbs-dev-src`, then fixed `ssh ... docker exec -i <validated64hexDockerId> bun run -` with fixed stdin JavaScript. No untrusted shell/code interpolation, credentials, alternative host/container, repository HEAD or production fallback. Inspection returns the immutable validated Docker ID and exec uses that ID, preserving the binding if the dev name is recreated between calls. Source provenance and OTLP `puni.target.container.id` retain this exact ID for the later log adapter; a new cycle re-inspects the current named dev container. Each read checks exactly one running `/wbs-dev-src`, `/src` working directory, `Cmd=["bun","run","dev"]`, only `wbs-dev-net`, a64hex Docker Id, and bind `/home/puni1/wbs-dev/src -> /src`. It reads container-local `http://127.0.0.1:3100/health` without redirect following. Only `{status:"ok",commit:<40 lowercase hex>}` is accepted; extra response fields are discarded. Request/OTLP bodies cap at 4096 bytes incrementally, subprocess stdout at 32768 bytes. Remote request timeout is 15 seconds within the outer 20-second cycle. Cancelling the local SSH process cannot prove instantaneous remote process destruction; its independently bounded read timeout remains in force.

Request duration uses `performance.now()` around the actual HTTP request and full bounded body read on the source host. `transportDurationMs` measures the separate complete SSH inspect/exec roundtrip. Epoch-ms child start/end are checked inside the root interval, including future and before-parent refusals; clock skew therefore fails visibly instead of clamping timestamps. Direct `createHttpHealthReader` only allows unauthenticated `http://127.0.0.1:<port>/health` and explicitly marks `source.kind=local-http-rehearsal`. SSH source marks `ssh-dev-container` plus a discriminated `containerValidated`/`containerId` pair; container/mount provenance is emitted only after inspection. Local fixture evidence cannot authorize real-dev acceptance.

`readCheckpoint(path, initialize)` requires readable valid existing state; first start is explicit exclusive initialization, never an implicit missing-state default. `writeCheckpoint` atomically replaces one bounded 8-KiB sanitized observation, without history. It records request identity/time, actual revision, source provenance, request/publication outcome and span IDs. CLI seeds previous revision metadata only from an acknowledged checkpoint. If publication failed or no checkpoint observation exists, previous active backend revision is unknown: acceptance must remain incomplete if multiple active revisions exist until exporter expiry. Checkpoint schema is the ProbeObservation structure, or explicit `{state:"empty"}`.

## OTLP and acceptance correlation contract

HTTP200 with `{}` or standard empty/zero `partialSuccess` is acknowledged; malformed/oversized acknowledgement, nonzero rejections, nonempty error message, non200 and transport outage fail. No retry queue or lossless delivery claim. A failed publish may have emitted earlier signals; acceptance must query all stores.
