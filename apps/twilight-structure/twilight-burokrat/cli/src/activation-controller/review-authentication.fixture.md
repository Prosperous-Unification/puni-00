# Test-owned offline attestation fixture

`review-authentication.fixture.ts` generates a new private CA, signing leaf, and timestamp-authority key for each test. The issuer organization `GitHub, Inc.` selects the GitHub policy in gh's custom-root verifier; the name does **not** make these keys or certificates GitHub evidence. The tests compute their own runtime and root identities solely to exercise the process contract. `/usr/bin/gh` is a test executable, not an independently protected production pin.

The generator uses `openssl ecparam` for three P-256 keys, `openssl req` and `openssl x509` for a self-signed test CA and separate leaf/TSA certificates, and `node:crypto.sign` over DSSE PAE bytes. It runs `openssl ts -query -data signature.bin -sha256 -cert` and `openssl ts -reply -queryfile request.tsq -config tsa.cnf` to timestamp the raw DSSE signature. It writes a v0.3 bundle with only the leaf certificate and an RFC3161 timestamp, plus a one-line custom `trusted_root.jsonl` ending in `\n`. All files live in a mode-0700 temporary directory, and the tests remove it after each case. No private key is checked in.

From the repository root, run `bun test apps/twilight-structure/twilight-burokrat/cli/src/activation-controller/review-authentication.test.ts` to regenerate the material for each test and invoke the real offline `/usr/bin/gh` verifier. `createTestOwnedReviewAttestation` returns the private temporary directory, exact manifest and bundle bytes, trusted-root path, and a `dispose()` cleanup callback. The leaf config carries test URI SAN and Fulcio CI extension values; the TSA leaf has a critical exclusive timestamping EKU. The generator never imports a production root or key.

The extension OIDs and ASN.1 UTF8String encoding follow [sigstore-go v1.3.0's Fulcio parser](https://raw.githubusercontent.com/sigstore/sigstore-go/v1.3.0/pkg/fulcio/certificate/extensions.go). The timestamp covers the signature bytes as [sigstore-go's TSA verifier](https://raw.githubusercontent.com/sigstore/sigstore-go/v1.3.0/pkg/verify/tsa.go) requires. The bundle/root shapes follow [Sigstore's bundle schema](https://raw.githubusercontent.com/sigstore/protobuf-specs/main/protos/sigstore_bundle.proto) and [trusted-root schema](https://raw.githubusercontent.com/sigstore/protobuf-specs/main/protos/sigstore_trustroot.proto). The final newline and issuer-based custom-root policy follow [gh v2.98.0's verifier](https://raw.githubusercontent.com/cli/cli/v2.98.0/pkg/cmd/attestation/verification/sigstore.go).

An exit-zero test here proves that gh verifies a synthetic signature against a synthetic root and policy. Altered `verificationResult` tests prove application parser guards only; the separately reissued certificates and re-signed predicates distinguish gh policy refusal from application refusal. None establishes a production root, real GitHub run, protected resolver, producer parity, authenticated metadata, or receipt authority.
