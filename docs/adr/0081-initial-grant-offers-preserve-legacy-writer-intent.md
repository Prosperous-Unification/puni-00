# Initial access offers preserve legacy-writer intent

An invitation or approved join request records explicit initial access: none or one of the four permitted catalogue roles. We persist a bounded none/role selection and reserve SQL NULL for an old writer omitting the new field; additive backfill and a narrow insert trigger translate every historical or old-writer admin/member/viewer offer into org-admin/project-contributor/project-viewer. This preserves offered authority instead of silently stripping it or interpreting omitted legacy fields as explicit no access; runtime authorization reads only the new validated selection.

The old role column remains coherent for the three reversible selections; none and org-viewer use a viewer compatibility placeholder only for schema compatibility. Rollback refuses before effects if any historical row has a nonrepresentable selection, malformed selection or inverse mismatch. This retains offer history rather than rewriting or deleting evidence to permit rollback. The trigger preserves offers only: acceptance and onboarding must be routed to upgraded grant-and-audit owners or quiesced before live cutover. It cannot make old binaries enforce the new grant policy.

Deployment clarification: outgoing binaries still interpret the compatibility viewer column. Before migration, outgoing acceptance/onboarding mutations must be quiesced; before exposing upgraded grant semantics, outgoing authorization readers and existing gateway/WebSocket sessions must be retired or drained, or activation refused. This required task6.4 boundary must preserve actual read availability and rollback contracts.
