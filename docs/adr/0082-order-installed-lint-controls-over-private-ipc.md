# Order installed lint controls over private IPC

Bun1.4.4 native probes showed pre-handler SIGTERM terminates the launcher, repeated SIGINT can coalesce and mixed SIGINT/SIGTERM can arrive in reverse order. The installed parent therefore uses a private versioned Bun IPC lane: the launcher installs its existing interrupt/output owners and channel handlers before ready, queued interrupts arrive in order before start, and only start permits operation IO. Controls feed the same first-reason broker; its existing stage owner alone signals and escalates detached stages. Installed invocation uses the distinct closed --puni-lint-parent-v1 marker, so an older v1-only launcher rejects it before work instead of ignoring an environment opt-in. After the handshake, constant internal dispatch enters the unchanged --puni-lint-v1 request core; it never reparses user argv. The archive/direct launcher keeps its native-signal contract.

A final finished notice follows executable lifecycle settlement, distinguishing normal IPC closure from premature channel loss; it also covers explicit cleanup failure with retained scratch and exit1, and never proves detached group absence. Small finished frames arrived before disconnect in30 protected-launch trials at exits0/1 on the pinned runtime, so no separate acknowledgement is justified. The executable removes channel listeners and exits immediately; reusable parent APIs await child and pipes. Parent output failure requests child-owned termination, discards/drains further output and retains stderr; unsolicited launcher death reports nested cleanup unconfirmed. There is no competing parent escalation timer after start. Native signal replay, a PID-only relay and inferring stage absence from launcher-group disappearance were rejected. Evidence and actual delivery checks belong to the [PUNI change](../../openspec/changes/puni-cli/verify.md).
