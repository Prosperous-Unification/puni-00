# Version the Bun toolkit execution format

The former toolkit descriptor schema 1 and activation manifest schema 3 fix a Bash launcher path and execution contract. PUNI's Bun launcher uses toolkit schema 2 with `launcher.mjs` and activation schema 4 with `artifacts/launcher.mjs` (bootstrap `bootstrap-launcher.mjs`); changing those layouts under their old schema would silently reinterpret historical authority. Keep the closed role roster, original-byte verification and identities for historical formats, separately from current execution compatibility: new Bun execution refuses historical formats before launching, while historical verification does not require today's Bun to equal the historical runtime. Current execution retains its exact Bun pin. Do not infer an interpreter from a shebang, fall back to Bash, or rewrite old bytes.

The package manifest stays schema 1 and changes its actual package/toolkit identity; selected.json stays schema 1, the active-v1 marker and validator request transport v1 keep their contracts. The snapshotter remains snapshotter.ts and is selected from the authenticated activation, receiving a protected launch prefix from its caller. Bundle the [shared startup composer](../../libs/shared/adapters/bun-startup/src/index.ts) into delivered roles; do not ship unresolved workspace aliases. Activation verification authenticates its role/descriptors, not the archive-root trusted-node-modules tree: the selected toolkit/transport and physical closure boundaries still own that authority. The [PUNI change](../../openspec/changes/puni-cli/design.md) owns the coordinated producer/consumer switch and its evidence.

Supported historical toolkit schema 1 means the pre-migration five-role layout, including launcher.sh and prepare-relocation-activation.mjs, with verified trustedNodeModulesIdentity. Earlier four-role or closure-unbound layouts remain unsupported, as in the baseline reader. Role maps now reject additional digest entries that the former reader ignored without verifying their files; this deliberately tightens validation while preserving the supported producer layout. It does not preserve every input accepted by that permissive parser. Do not synthesize missing roles/closure identities or add archive-transport authority to descriptor verification.
