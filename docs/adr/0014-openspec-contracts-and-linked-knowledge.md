# OpenSpec contracts and linked knowledge

The user accepted this authority split during Twilight discovery on 2026-09-06:
OpenSpec owns testable requirements, while the domain wiki explains and cites
them. We retain that split because making wiki prose canonical requirements
would change how specification discovery, review, and synchronization work
across existing and generated repositories. A factory-owned replacement would
add a second workflow authority before the first one is proven.

The wiki retains sources, provisional claims, contradictions, and links to
evidence; it cannot silently promote a source into a requirement. Code-symbol
knowledge remains in JSDoc and context vocabulary remains in its owning glossary.
This decision records the prior accepted direction, not approval of the proposed
runtime, new workflow schema, or future production operations.
