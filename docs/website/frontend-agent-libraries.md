# Frontend agent chat libraries for PUNI

Research checked 2026-09-28 against official product documentation and source repositories. This is a selection note, not an implementation decision or a claim of runtime compatibility in PUNI.

## Fit to the current app

The public app is already React 19/Vite with ordinary CSS and a credentialed `fetch` wrapper. Its Bun API owns the prospect session, CSRF check, account scoped turns, 12 turn cap, provider reservation, OpenRouter call, and concept record. `GET /chat` restores turns; `POST /chat` currently returns one JSON reply after a nonstreaming OpenRouter call. The Astro landing page sends the initial description to `/intakes`; after sign in it becomes an unsent composer draft. These facts are visible in [`fe-01/src/main.tsx`](../../apps/website/fe-01/src/main.tsx), [`fe-01/src/api.ts`](../../apps/website/fe-01/src/api.ts), [`be-01/src/server.ts`](../../apps/website/be-01/src/server.ts), and the [funnel design](../../openspec/changes/puni-website-funnel/design.md).

The design deliberately has no model selected in the browser, browser tools, generated executable code, or automatic retries. The API must remain the authority for account ownership, turn and spending admission, provider usage settlement, and the safe typed concept renderer. A chat library can display those states; it cannot replace those controls.

## Cross-cutting costs and boundaries

- **Persistence and ownership.** assistant-ui offers a `ThreadHistoryAdapter` and a remote thread list for a host database; the AI SDK integration requires its `withFormat` history variant. These are frontend adapters, not account authorization. PUNI should continue to load and write only the server-owned request associated with the authenticated session. [assistant-ui custom persistence](https://www.assistant-ui.com/docs/integrations/persistence/custom-adapter), [AI SDK persistence](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot-message-persistence)
- **Streams and spending.** An AI SDK UI stream has a specified SSE header and start/delta/end parts. Server logic must settle a reservation from confirmed provider usage and make disconnect, timeout and cancellation explicit; displaying a partial message proves no final usage. AI SDK itself discusses disconnect handling and server consumption separately from chat storage. [Protocol](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol), [disconnects](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot-message-persistence)
- **Tool cards and approvals.** All three UI ecosystems offer approval surfaces, but the server must be the authority to approve an effect. assistant-ui documents server approval gates and host-owned persistence of approval decisions; AI Elements has a display component backed by AI SDK tool approval; CopilotKit has human interruption patterns. None is needed for M2 because its model has no tools. [assistant-ui](https://www.assistant-ui.com/docs/tools/tool-ui), [AI SDK](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot-tool-usage), [AI Elements](https://elements.ai-sdk.dev/components/confirmation), [CopilotKit](https://docs.copilotkit.ai/agent-spec/human-in-the-loop/useInterrupt)
- **Attachments and artifacts.** assistant-ui and AI Elements have attachment UI, yet PUNI's current input contract is text and its M3 artifact is a server validated `Concept` rendered from fixed safe components. Uploads need storage, content validation, provider compatibility and retention rules before enabling attachment buttons. [assistant-ui attachments](https://www.assistant-ui.com/docs/runtimes/ai-sdk/v7), [AI Elements prompt input](https://elements.ai-sdk.dev/components/prompt-input)
- **Licenses and hosted services.** The assistant-ui repository is MIT and its Cloud is optional; AI SDK and AI Elements repositories are Apache-2.0; CopilotKit source is MIT and offers separate Intelligence services. These repository licenses do not establish terms for optional cloud products. [assistant-ui repository](https://github.com/assistant-ui/assistant-ui), [AI SDK license](https://github.com/vercel/ai/blob/main/LICENSE), [AI Elements license](https://github.com/vercel/ai-elements/blob/main/LICENSE), [CopilotKit repository](https://github.com/CopilotKit/CopilotKit)

## Recommendation

Target **assistant-ui + AI SDK with streaming** for the full Build experience. It offers a capable React chat surface and typed message/tool states while letting PUNI retain its Vite app, Bun API, and server-side OpenRouter integration. Implement an AI SDK UI message stream at the API boundary, map stored account-owned turns into thread history, and verify credentialed cross-origin requests, CSRF, cancellation, final usage and unsettled reservations before exposing live inference. The preview should sit beside chat as PUNI's own panel, backed by its safe typed concept contract. [AI SDK integration](https://www.assistant-ui.com/docs/integrations/frameworks/ai-sdk), [stream protocol](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol), [persistence](https://www.assistant-ui.com/docs/integrations/persistence/custom-adapter)

**assistant-ui LocalRuntime** remains a lower-effort transitional path if the existing JSON `GET/POST /chat` contract needs to ship before streaming. Its REST adapter fits that shape, but client edit, retry and branching controls must follow server paid-turn semantics. Defer AI Elements unless the app intentionally adopts Tailwind/shadcn; defer CopilotKit/AG-UI until it has a multi-step agent or shared agent state that justifies its protocol. [LocalRuntime](https://www.assistant-ui.com/docs/runtimes/custom/local-runtime), [AI Elements setup](https://elements.ai-sdk.dev/docs/setup), [AG-UI connection](https://docs.copilotkit.ai/agent-spec/backend/ag-ui)

No packages were installed and no compatibility test was run. The findings are a source-backed design comparison only.
