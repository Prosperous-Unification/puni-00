# Website walkthrough

The reviewed visitor journey, one row per scenario, each mapped to the capture or test that shows
it. It replaces the 2026-09 [prototype](prototypes/README.md), whose twelve-turn, signed-in
sequence predates [ADR 0039](../adr/0039-anonymous-paid-chat-bound-to-the-browser-claim.md).

Evidence prefixes name the file that declares the case:
`screens.mjs` is a capture state in `apps/website/fe-01/browser/screens.mjs`,
`conversation.mjs` a numbered case in `apps/website/fe-01/browser/conversation.mjs`,
`conversation.test.ts` a test in `apps/website/be-01/src/conversation/conversation.test.ts`, and
`conversation-harness.test.tsx` a test in `apps/website/fe-01/src/conversation-harness.test.tsx`.
`apps/website/fe-01/src/walkthrough.test.ts` fails when a named case no longer exists.

The operator captures run only when `PUNI_OPERATOR_PASSWORD` is set. Fixture stacks and commands
are in [the polish verification](../../openspec/changes/polish-build-app-screens/verify.md) and
[the harness verification](../../openspec/changes/build-ai-chat-harness/verify.md).

Version-1 review uses the same request editor on chat, manual, disabled and paused routes. The
canonical brief body and optional references are saved separately under the current revision;
the readable final review composes them once, within 8,000 characters. Change this opens editing; Review request returns to prose. Contact/editing hides the chat composer while preserving its draft and in-flight Stop. Explicit Send my request
submits those exact bytes. Later AI candidates require acceptance and cannot replace unsaved
human edits. Danylo Fedorov reviews requests; the receipt confirms storage rather than email
delivery.

The scripted `apps/website/fe-01/browser/scoping.mjs` journey covers the six starters, the click-only
Improve path, mixed answers, stale tabs, corrections, reference purposes, unsaved reload,
fresh-tab/manual recovery, declined/reopened contact, early review, invalid output, Stop/Retry
and exact versioned lost-response replay. It uses the real admission and settlement boundary
with a deterministic provider fixture; it provides no evidence of model judgment.
