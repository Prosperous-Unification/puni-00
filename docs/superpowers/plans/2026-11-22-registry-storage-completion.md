> **For agentic workers:** Use `superpowers:executing-plans` when implementation is explicitly resumed. Read the owning OpenSpec artifacts before each slice. The checkboxes below are completion gates, not permission to resume.

**Goal:** Make the remaining registry scope reviewable, reconcile the recorded Harbor choice with the unfinished storage objective, and sequence a safe implementation and production cutover.

**Architecture:** Harbor is the recorded replacement direction. Its existing source slices and attended production steps remain the implementation plan; this roadmap supplies their prerequisites, acceptance gates and the unfinished custom scope that needs an explicit disposition. It changes no runtime behavior or success criterion.

**Tech Stack:** Bun, Nx, OpenSpec, Ansible, Flux, k3s, Harbor, Distribution and restic. Component versions remain those in the selected design and toolchain lock; revalidate them before implementation.

**Spec:** [Harbor proposal](../../../openspec/changes/adopt-harbor-registry/proposal.md), [design](../../../openspec/changes/adopt-harbor-registry/design.md), [tasks](../../../openspec/changes/adopt-harbor-registry/tasks.md), and the original [storage proposal](../../../openspec/changes/bound-registry-storage/proposal.md), [design](../../../openspec/changes/bound-registry-storage/design.md), [spec](../../../openspec/changes/bound-registry-storage/specs/registry-storage-lifecycle/spec.md) and [tasks](../../../openspec/changes/bound-registry-storage/tasks.md).
