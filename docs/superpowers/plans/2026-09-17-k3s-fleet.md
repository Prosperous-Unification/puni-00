# Dynamic k3s Fleet Implementation Plan

> **For agentic workers:** Use `executing-plans`. Execute F0–F12 in dependency order; keep operation planning, local rehearsal and real-host acceptance distinct in the evidence.

**Goal:** Supply all node/bootstrap/deployment scripts needed to operate an evolving k3s fleet, with a usable localhost setup and rehearsed join, leave, replacement, upgrade and recovery paths.

**Architecture:** Ansible owns machines and k3s membership. A small Bun fleet controller validates desired/observed state and emits immutable operation plans. Flux owns steady-state platform resources; WBS deployment uses its own journaled coordinator so migrations and rollback remain explicit.

**Tech stack:** Bun/Nx, Ansible, Hetzner dynamic inventory plus explicit SSH inventory, Ubuntu 24.04 LTS initially, k3s, k3d, Flux, SOPS/age, Traefik, cert-manager, ECK, Prometheus, OTel, existing Dagger.

**Spec:** [F1–F6 in the delivery contract](../specs/2026-09-17-twilight-bureaucrat-and-fleet-design.md). The master plan's global constraints apply verbatim.

**Infrastructure baseline:** reuse [the merged September 15 proposal](../../plans/2026-09-15-infra-evolution-plan.md) and both reviews linked by the contract. Keep its Terraform/Ansible split, capability roles, Flux platform, Elastic/Prometheus/OTel and backup layers. The tasks below add implementation detail, node lifecycle and localhost proofs to that design.

## F1 — Define desired fleet and stable identities

**Files:** `infra/fleet/{desired.yaml,examples/local.yaml,examples/production.yaml}`, `tools/tool-fleet/src/{contracts,contracts.test,plan,plan.test,cli}.ts`.

**Interface:** export `Fleet`, `Observation`, `OperationPlan`, `decodeFleet(input: unknown): Fleet`, `planOperation(fleet: Fleet, observation: Observation, request: OperationRequest): OperationPlan`. Use strict schemas at file/API boundaries, then precise internal types. Suggested central shape:

```ts
type Capability = 'control-plane' | 'product' | 'ingress' | 'observability' | 'forge' | 'execution';
type Lifecycle = 'present' | 'draining' | 'retired';
interface FleetNode {
  readonly id: string;
  readonly cluster: string;
  readonly capabilities: readonly Capability[];
  readonly lifecycle: Lifecycle;
  readonly provider:
    | { readonly kind: 'hcloud'; readonly instanceId: string }
    | { readonly kind: 'ssh'; readonly machineId: string; readonly address: string };
}
interface Cluster {
  readonly id: string;
  readonly purpose: 'platform' | 'workers';
  readonly apiEndpoint: string;
  readonly controlPlane: 'single' | 'ha';
  readonly requiredCapabilities: Readonly<Partial<Record<Capability, number>>>;
}
interface Fleet {
  readonly schemaVersion: 1;
  readonly revision: string;
  readonly clusters: readonly Cluster[];
  readonly nodes: readonly FleetNode[];
}
```

`requiredCapabilities` is an explicit subset, not a default for missing cluster policy. Validate unique node/cluster IDs, nonempty capabilities, integer floors, supported combinations, server topology and separate execution/platform placement. An enrolled host must have a provider identity; provisioning requests are a separate type until creation returns one.

- [ ] Write fixtures for a platform with combined product/ingress server plus observability agent, a worker server plus two agents, a fourth arbitrary hostname, and an invalid cross-cluster duplicate instance.
- [ ] Test joins without editing role code; test unknown capability, missing instance ID and duplicate identity refuse.
- [ ] Add request union `enroll | retire | replace | upgrade | provision | destroy`; all target an explicit node/cluster or a separately validated provisioning request. `discover` never implies `destroy`.
- [ ] Add JSON output to `tool-fleet:plan`; output includes desired revision, observation digest/time, target identities, preconditions, ordered effects and a plan SHA-256. Human summary shows affected capabilities and downtime/storage implications.
- [ ] Run `bunx nx run tool-fleet:test --skip-nx-cache`. Commit the schema and planner's first negative proofs.

- [ ] Create two disposable Ubuntu VMs through the lab helper for platform role convergence, and a three-node worker lab when resources allow. Use a supported local VM provider (Multipass on macOS/Linux or libvirt on Linux), pinned in the tool lock. Lab creates uniquely prefixed VMs and refuses to operate on arbitrary host names.
- [ ] Test the initial failure with the bootstrap playbook absent, then implement the real roles: operator account/authorized keys, sudo boundary, chrony, package prerequisites, journald limits, mount verification, k3s sysctls and explicit swap configuration.
- [ ] Render firewall rules by cluster capability/interface. Keep SSH recovery access while validating a new rule set; do not flush unrelated host policy. Open Kubernetes/etcd/VXLAN/kubelet traffic only as required between enrolled private addresses. Verify cross-node MTU with a nonfragmenting probe and actual pod traffic.
- [ ] Fetch pinned k3s artifacts with Ansible `get_url` checksum validation, render `/etc/rancher/k3s/config.yaml`, install systemd units and start. Server config uses embedded etcd, secrets encryption, named private node IP/interface, explicit TLS SAN/API endpoint, disabled bundled Traefik/ServiceLB and cloud-controller selection appropriate to the profile. - [ ] Apply twice on clean VMs. Assert the second play's recap has no unexplained changes; explicitly mark observation commands `changed_when: false` only when they perform no mutation. `--check` alone is insufficient evidence.

## F4 — Provision and enroll arbitrary new nodes

**Files:** `infra/terraform/{main,variables,outputs,versions,backend}.tf`, `infra/terraform/.terraform.lock.hcl`, `tools/tool-fleet/src/{apply,apply.test,journal,journal.test,terraform,terraform.test}.ts`, `infra/fleet/schemas/operation-plan.json`.

**Consumes:** F1/F2 plan + F3 roles. **Produces:** `applyOperation(plan: OperationPlan): Promise<OperationReceipt>`, a durable journal with operation/step IDs, external resource IDs, before/after observations and explicit terminal state. Files use atomic replacement and owner-only permissions; corrupt or unreadable journals throw.

- [ ] Provisioning is a separate operation naming cloud account, region, machine type, image, network, SSH key IDs, retained storage and budget cap. Reuse the earlier proposal's Terraform hcloud provider for server/network/firewall/primary-IP/volume ownership. Key resources by stable logical node ID with `for_each`, not list position. Removing one node must not renumber or recreate its neighbors. Import existing resources explicitly; no implicit take-over by name.
- [ ] Configure encrypted, access-controlled, versioned remote state with locking before concurrent use. Store backend credentials outside Git. Ansible reads cloud inventory/validated Terraform outputs but never manages those same cloud resources. Provider versions live in the Terraform lockfile; Nx wraps a checksum-locked Terragrunt 1.1.5 runner with Terraform 1.16.3 explicitly selected: `init -lockfile=readonly`, `validate`, `plan -out`, `show -json`, and apply of that exact saved plan. The source-free in-place Terragrunt unit is digest-bound to each operation; implicit init/retries and ambient execution overrides refuse.
- [ ] Bind the Terraform plan digest/state serial/lineage to the F1 operation plan; reject stale state, destroy/replace actions outside the named operation and unintended storage deletion. Protected volumes/primary IPs use lifecycle safeguards and explicit separate retirement. A provider destroy may only consume a completed F5 retirement receipt for the same instance.
- [ ] Test a create call whose response is lost after the server exists. Re-observe cloud ownership and state, then reconcile/import the exact operation-owned instance under a fresh reviewed plan; never blindly rerun creation or buy a second machine. Duplicate ownership labels refuse.
- [ ] Join the newly created instance into desired state only after receiving and recording its provider identity, then execute F3 Ansible enrollment. Run the same configuration path on an existing authorized SSH host using verified machine ID and SSH host key; it remains outside Terraform ownership unless explicitly imported.
- [ ] Apply accepts only a persisted plan path and expected digest. Before each mutation check lease/lock ownership and relevant preconditions; refresh resource versions that the operation itself changes while preserving identity. Every read has a bounded timeout; retries converge to an explicit predicate or fail with journal state.

```sh
bunx nx run tool-fleet:plan -- --fleet infra/fleet/desired.yaml --operation enroll --node worker-c --output /tmp/enroll-worker-c.json
bunx nx run tool-fleet:apply -- --plan /tmp/enroll-worker-c.json --expect-sha256 "$FLEET_PLAN_SHA256"
```

`FLEET_PLAN_SHA256` is the printed digest the operator reviewed, not a value silently recomputed by apply. The normal plan command never calls a mutating provider API.

- [ ] Production-path tests: stale plan, same-name replaced instance, concurrent operation, lease expiry, interrupted journal write and unknown completed step all stop mutation. The negative that disables identity recheck must demonstrate an attempted wrong-instance mutation in the controlled adapter and fail.
- [ ] Add a node with a new hostname/capability assignment through inventory, observe it Ready, rerun apply as an idempotent no-op, and commit the observed receipt.

## F5 — Drain, retire, replace and upgrade without fixed hosts

**Files:** `infra/ansible/playbooks/{retire,upgrade}.yml`, `tools/tool-fleet/src/{retire,retire.test,replace,replace.test,upgrade,upgrade.test}.ts`, `docs/infra/fleet.md`.

**Produces:** pure `planRetirement(fleet, observation, nodeId)` transitions consumed by F4. A provider destroy action is a distinct plan after retirement; it never deletes storage by default.

- [ ] Unit-test the planning rules, then exercise each through `tool-fleet:plan/apply` in k3s. A representative test after the fixture constructors are added to `src/testing/fleet.ts`:

```ts
test('a failed provider observation cannot retire the last ingress node', async () => {
  const invocation = Bun.spawnSync(
    [
      process.execPath,
      'tools/tool-fleet/src/cli.ts',
      'plan',
      '--fleet',
      fixturePath,
      '--operation',
      'retire',
      '--node',
      'edge-a',
    ],
    { env: { ...process.env, PATH: failingProviderPath }, stdout: 'pipe', stderr: 'pipe' },
  );
  expect(invocation.exitCode).not.toBe(0);
  expect(invocation.stderr.toString()).toContain('provider observation failed');
  expect(existsSync(mutationSentinel)).toBe(false);
});
```

The test itself creates `fixturePath`, `failingProviderPath` and `mutationSentinel` in its own scratch directory; the fake provider exits 42. Add a separate valid observation test for last-ingress refusal so API failure cannot hide the capability rule.

- [ ] Retirement sequence: confirm replacement capacity/storage topology and backup status; cordon; evict through the API respecting PDBs; wait for rescheduled workloads and volume detach; verify no unmanaged/static or local-state workload remains; stop and disable the node's k3s service; remove its enrollment configuration and node credentials without deleting retained application state; remove Kubernetes/etcd membership; preserve an auditable retired record; separately plan provider shutdown/deletion. Remove the node from enrollment inventory before issuing the retirement receipt. Shared join tokens are not per-node revocation: where an old host cannot be trusted to discard credentials, verify an external fence and rotate compromised credentials before completing retirement.
- [ ] Reboot a retired disposable SSH node while the cluster remains reachable and observe that it does not re-register. Inject a retained enabled k3s service/credential through the production retirement path and require the de-enrollment verification to refuse the completion receipt. A node that cannot be reached for de-enrollment requires verified fencing, not an assumed successful shutdown.
- [ ] Exercise PDB blocking, local PV, forge worktree, and singleton SQLite cases. Each requires an explicit migration/maintenance transaction and must fail the generic drain. Do not add `--force` or `--delete-emptydir-data` as universal remedies.
- [ ] For control-plane nodes, use etcd member health/count and API endpoint placement. Never remove the sole server via ordinary retirement. In an HA expansion, add and prove replacements first, keep a majority healthy, remove one member at a time and refresh the topology before the next operation.
- [ ] Dead-node replacement requires evidence the old instance cannot resume: provider powered-off state/retirement or a verified external fence. Only then detach/reassign storage and allow a replacement writer. If fencing cannot be verified, report blocked recovery with the exact node/resource IDs.
- [ ] Upgrade servers serially before agents, from a pinned tested version; snapshot etcd/token first and prove health after each. OS reboots are also serial and placement-aware. A server downgrade uses the documented restore procedure, not an assumed supported binary rollback.
- [ ] Rehearse new worker join → running Job → planned drain → node disappearance → replacement with a different instance identity. Assert no duplicate mutation, correct fault state, and surviving service/record. Commit the lifecycle code and concrete drill results.

## F6 — Install the platform with explicit ownership

**Files:** `infra/clusters/{platform,workers}/{local,production}/`, `infra/platform/{networking,storage,policy}/`, `infra/ansible/playbooks/platform.yml`, `docs/infra/platform.md`.

**Consumes:** Ready k3s nodes and F0 locks. **Produces:** pinned Flux reconciliation with health gates and SOPS secrets, using cluster-specific namespaces/identities and no production secret in the local overlay.

- [ ] Bootstrap Flux through a dedicated read-only repository deploy key where possible; its bootstrap write credential is temporary and distinct. Ansible installs/configures hosts; Flux owns installed platform Kubernetes objects afterward. Do not have both reconcilers manage the same HelmRelease/Secret fields.
- [ ] Stage CRDs/controllers before dependents: cloud CCM/CSI, storage classes, Traefik, cert-manager, policy, then monitoring/backups, then products. Disable bundled k3s components that Flux replaces. A missing CRD or failed HelmRelease blocks dependent reconciliation.
- [ ] Production registry access must work from node containerd and Dagger with TLS/auth using a stable private endpoint. Initially retain the known working image registry while provisioning equivalent registry manifests and a tested migration. Local uses a dedicated test registry. Registry garbage collection takes read-only/offline mode and proves pulls after restart.
- [ ] Use explicit product/staging hostnames and staging ACME first. DNS changes are a separately reviewed operation listing previous/new records, TTL and rollback. The local profile uses test certificates and loopback-only access. Keep Kibana/Grafana behind private access.
- [ ] Restricted Pod Security for ordinary product/worker namespaces, explicit quotas, non-default service accounts, no automounted API credentials for workers, default-deny NetworkPolicies plus DNS/ingress/telemetry allowances. The current backend's host-owned solver socket requires the narrow trusted namespace exception below. Test denied cross-namespace traffic with pods, not only rendered YAML.
- [ ] Place only the solver-dependent backend in a dedicated trusted `wbs-solver` namespace: neither Restricted nor Baseline Pod Security permits its hostPath. Enforce equivalent workload restrictions through explicit admission, allowing only the exact configured solver runtime directory (`Directory`, never a socket inode or broad parent), approved backend digest/controller/service account and product-capable placement. No Docker socket, privileged container, host PID/network or privilege escalation is allowed. Keep gateway/frontend/MCP in restricted namespaces; explicitly render cross-namespace service addresses and narrowly scoped network policies. Untrusted users cannot create workloads or impersonate the trusted service account there. F8 must prove solver operation and denied alternate host paths before adoption.
- [ ] Source-run forge uses a separate trusted namespace with admission restricting exact worktree roots, pod owner/service account, no privilege escalation and no Docker socket. RBAC grants only the dev-environment controller the ability to create hostPath pods there. Ordinary users cannot create a pod using that service account through their own permissions.
- [ ] Test bad chart digest/version, missing decryption key, disallowed hostPath, untrusted service account and wrong-cluster kubeconfig. Each must refuse before a privileged workload runs. Commit the manifests and local conformance tests.

## F8 — Build the WBS Kubernetes release transaction

**Files:** `deploy/k8s/wbs/base/{backend,gateway,frontend,mcp,storage,network-policy,kustomization}.yaml`, `deploy/k8s/wbs/overlays/{local,staging,prod}/`, `tools/tool-deploy/src/k8s/{release,execute,journal}.ts` and matching tests; add Nx `deploy:k3s`, `test:k3s` targets to `tools/tool-deploy/project.json`.

**Read before coding:** `tools/tool-remote-scripts/src/{swap,swap.test}.ts`, `src/lib/{deploy-contract,drain}.ts`, `tools/tool-deploy/src/migrations.test.ts`, backend migration-status/down CLIs, all four tier Dockerfiles/config contracts, solver supervisor setup. Reuse pure existing migration/digest/health helpers where they fit.

**Interface:** `planRelease(request: ReleaseRequest, state: ReleaseState): readonly ReleaseStep[]`. `ReleaseRequest` requires cluster identity, namespace, source SHA, per-tier image digests, expected current release identity and admission evidence. `ReleaseState` records phase, captured migration set, old digests, snapshot identity, Flux suspension ownership and whether writes reopened. Reject unknown phases.

- [ ] Write state-machine tests for this order, including an injected crash after every durable phase:

```text
validate identity/admission → acquire Lease → persist intent → suspend named WBS reconciliation
→ close writes/maintenance ingress → drain gateway → stop backend and prove no writer
→ capture migrations + verified snapshot → migration Job → backend readiness/auth
→ gateway/frontend/MCP readiness → smoke → persist new release → reopen writes
→ reconcile committed desired revision → resume WBS Flux → release Lease
```

The coordinator waits until Flux confirms the WBS unit is suspended before temporary replica/image changes. On resume it verifies the Git source revision contains the successful release, so Flux cannot restore an old digest. Platform reconciliation remains active throughout.

- [ ] Implement bounded process/API adapters and a durable journal outside ephemeral Jobs. Kubernetes Jobs can start twice: migration execution uses the release lock and captured set, not Job completion alone. Set `MIGRATE_ON_STARTUP=false` for the new backend so the migration Job is the single migration actor.
- [ ] Render single-replica backend with no overlapping rollout, a PVC that survives deploy, proper UID/permissions, termination deadlines and health/auth probes. Test access mode on the actual CSI driver before selecting RWOP. Support a local storage class with explicit single-node constraints in the lab.
- [ ] Model failures before writes reopen as rollback of applied migrations to the captured set and old digests, then health/smoke before reopening. Edited down migrations refuse. Test timeout, failed health, failed smoke and failed rollback; the last leaves writes fenced and prints the exact manual command, captured migration set and journal path.
- [ ] Model failures after writes reopen as `recovery-required`; do not reuse a stale snapshot or perform a blind old-image rollout. A new recovery request must preserve acknowledged writes and be tested against a row written after promotion.
- [ ] Account for solver ownership explicitly: retain the host-owned supervisor on a product-capable node, managed by Ansible, with its runtime-directory mount and image compatibility checks; use F6's dedicated trusted backend namespace and keep placement bound to that capability until a separate portable solver service exists. Prove backend admission, a real solve, socket replacement/reconnect and refusal of a different host path/unapproved workload in the Ubuntu VM lab. Node removal is blocked until solver/runtime state transfers. Do not silently run the supervisor in the untrusted worker cluster.
- [ ] Run real local k3s integration: insert row, upgrade with additive migration, induce health failure, confirm old application/schema/row and blocked failure state as applicable. Prove at most one writer even during interrupted rollout. Commit and record each fault.

## Deliberate limits

Automatic purchase/autoscaling based on queue load, multi-region active-active products, a WBS database-engine migration and replacement of the Twilight scheduler are outside this implementation. Explicit Terraform provision/destroy plus Ansible enroll/retire/replace operations support new nodes coming and going; those operations must work before any later automation drives them.
