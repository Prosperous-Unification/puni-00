# Preparing a fixed reader before guarded controllers

Private proposed runbook; no host action is authorized by publication of this text. Independent target/artifact selection and the actual deployment authority are prerequisites. No command below is an automatic fallback from a failed controller.

## Select the route before any install

Read actual target/account and fixed state/Bun/reader status with the existing approved administrative read path. Do not infer freshness from a controller error. If any existing state is malformed, unreadable, partial or identity-uncertain, stop for attended recovery; do not delete it to fit either route.

**Fresh account/target:** independently selected normal account/home preparation happens first, separately from bootstrap/configure: puni1 UID/GID1000, canonical home, private owned cache parent and required fixed-path ancestor directories, ordinary required tools, no services/mappings/configuration/start. This account preparation is a separate existing provisioning prerequisite, not permission to run the whole gate_host/bootstrap role or change policy. Validate parents/ownership before the selected first-reader operation. Only genuinely absent policy/markers/Bun/reader can use it.

Invoke the existing installer `--prepare-first-reader` branch with the complete current required flags: host, target-hostname, account, uid, gid, fresh-target=independently-designated-fresh, and bun/reader/initializer paths, sha256 and bytes; all in --name=value form, plus explicit --execute only when separately authorized. First inspect its dry-run plan, compiler/source closure and independent artifacts. The selected reader must contain the new singleton controller checks. The existing operation owns actual initializer/origin receipt, lock reacquisition and no-replace publication. It does not update an existing reader. After known completion, under a newly retained existing edge interval execute both installed new singleton CLI checks with its real inherited OFD; missing capability blocks controller adoption. No historical receipt or caller-ready flag substitutes for this readback. First-reader remaining38 proof cases remain held and rollout qualification is not implied here.

**Existing ordinary host with old fixed reader:** independently select the exact JC0 pre-controller implementation and expected installed Bun/reader plus new reader hashes/sizes. Use the explicit `--transition-controller-reader` grammar in the linked design. Inspect its dry-run plan and selected source/compiler/artifacts first. The real OLD fixed `--check-edge-policy-inherited` provides ordinary/OFD authority. The explicit transition replaces only the reader, without replacing Bun or touching service/config/unit. Its new staged checks are capability tests, never initial authority. If the old boundary does not exist or refuses, stop; neither normal installer nor first-reader is a fallback.

**Already prepared reader:** retain existing edge interval and run the new fixed singleton required/legacy check chosen by the controller roster. No preparation is needed merely because a new caller is executing. An earlier preflight never authorizes later checkout/reset/write.

Only after the appropriate route and capability qualification may the new guarded normal controllers be installed/used under their own admission. Unsupported bootstrap/configure/install/adopt on active/restoring remain refused. Successful reader-file transition says nothing about the code already loaded by a running solver; the later actual solver eligibility/process/readiness and complete publisher/ingress/archive/terminal/successor handoff remain mandatory. No service restart, native capacity, architectural main/deploy or held proof authority is granted here.

## Existing provisioning boundary

Stable infra/ansible/roles/base/tasks/main.yml creates the fleet operator, not this selected fixed UID account. gate_host/tasks/main.yml creates a system gate account with Docker membership and does not pin UID1000; neither entire role is a substitute for the fresh-target prerequisite. Before first-reader on a truly new host, separately authorized account administration must verify no conflicting name/UID/GID/home, establish the selected puni1/1000/1000 home and minimal canonical private staging ancestors, then read them back. Do not renumber an existing account, chown an existing installation, run full-role convergence or create solver/config/service state to force the preparation route. An account mismatch is an explicit blocked prerequisite. Concrete authenticated host commands and their authority are intentionally outside this local source contract, consistent with verify-first-reader-preparation.md; no claim of an already available UID-pinned provisioning command. This does not leave the old-reader transition unspecified: JC0's public grammar, source/build, effects and actual authority are completely defined separately.
