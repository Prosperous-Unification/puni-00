# Security, reusable authentication and personal-assistant delivery

Assessment date: 2026-10-21. Source revision inspected and tested:
`4151532121633d978beb67ab52b3eb748285cd8e`. This is a read-only assessment against
[the requested scope](../../../puni-assessment.md), not authorization to activate
organizations, provision a client, rotate credentials or change an assistant.

PUNI has substantial WBS security implementation and useful bounded negative tests.
Those controls do not yet establish a repeatable, isolated client service. Organization
activation is a separate operational boundary; authentication alone does not separate
clients. Existing OpenClaw operations are an operator console, while the proposed
personal-assistant product remains a design and simulated UI. A dedicated, attended
client pilot is the defensible next evidence target; elapsed delivery time, recurring
effort and service guarantees cannot presently be quoted from this evidence.

## Delivery models and ownership consequences

The roles below are required owners, not assertions that people are staffed or contracts
signed. “Client owner” means the person authorized to decide information use and effects;
“identity administrator” owns provider/connector grants; “PUNI operator” owns the managed
runtime; “security lead” owns isolation acceptance; “application owner” owns authorization
and data semantics. Client-owned infrastructure still needs an agreed incident responder.

| Model                                            | Current applicability and principal consequence                                                                                                                                                                                                                                                                                                                                                                                                                | Required ownership/handover evidence                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared PUNI application/services                 | WBS can be reused as software; dev is now observed activated, but end-to-end client isolation is unverified and older production has no activation table. Pre-activation legacy access cannot be sold as client isolation. Existing OpenClaw operator gateway must not be assumed to isolate unrelated clients. | PUNI owns shared runtime/patches/incidents; client owns its information and grants; security lead accepts cross-client test matrix. ## OpenClaw: existing operation versus proposed product

[HUMAN_README](../../../HUMAN_README.md) records an OpenClaw operator on h1claw,
`security=full, ask=off`, with WhatsApp acting as a production console and access to
SSH/registry/GitHub authority. Its header dates verification to 2026-08-04; treat the
permission setting as a historical operational fact. Fresh coordinating-assessor metadata
observed an active `openclaw-gateway.service` labelled `v2026.7.1-2`, WhatsApp as the only
configured channel kind, and absent top-level `tools.exec.host/security/ask` fields.
`ssh h1claw openclaw --version` returned `OpenClaw 2026.9.4 (3a9d69d)`, establishing
the installed CLI identity and showing that the service description is stale. The running
gateway version was not independently established. Absent policy fields do not establish
effective policy: defaults, profiles and other policy sources were not resolved, so effective
permission rules remain unverified; see [live evidence](live-evidence.md).
The human runbook gives a recovery triage path through Tailscale, SSH, service restart and
`openclaw doctor`. That is useful operational knowledge, but it does not establish
least-privilege customer setup, a tested assistant backup or safe customer offboarding.
The latest h1 SQLite backup service run was observed failed, with repeated failure evidence
in its last 24 hours of journal output. Counts of matching log lines do not establish a count
of distinct backup attempts or the absence of older valid backups. Its scope is application
backups, so neither success nor failure would by itself prove assistant-state recovery.

The [assistant glossary](../../assistant/CONTEXT.md) defines secretary, worker and
assignment; the [work-view prototype](../../assistant/work-view-prototype.md) explicitly
has fictional in-memory content and calls no agents/external services. The separate
[OpenClaw boundary research](../../twilight-structure/research/assistant-runtime-boundary.md)
records upstream source inspected in September and says its live integration proofs were
not run. It proposes an adapter preserving Twilight's durable delivery authority. It
also records the upstream trusted-operator/team boundary as a customer-isolation concern.
This assessment relies on that as **historical design evidence**, not verification of
current upstream behavior or the installed gateway.

The proposed [assistant interaction contract](../../../openspec/changes/twilight-control-plane/specs/twilight/assistant-interaction/spec.md)
does not turn the existing powerful operator session into a client service. The website's
assistant-ui conversation is yet another surface: anonymous sales scoping, not an
OpenClaw-connected personal assistant.
