## Native infra checks and implementation gap

The native checker is a distinct contract. [check.ts](../../../tools/tool-fleet/src/check.ts) declares schema, strict YAML, Ansible syntax/inventory, kustomize, WBS backup, Helm, shellcheck, workflow and executable families. [check-provision.ts](../../../tools/tool-fleet/src/check-provision.ts) provisions digest-locked tools and requires a controller image; [infra-check.yml](../../../.github/workflows/infra-check.yml) builds that image and runs the Nx check on an ephemeral runner. None of those native checks or host operations was run for this research. A Burokrat classification observation does not stand in for their execution.

The highest priority implementation gap is a **production rule-by-subject applicability boundary tied to the exact committed inventory**. It should retain unsupported infra semantic families as unevaluated, require explicit reviewed reasons for inapplicability, bind candidate/tool/policy/adopted-set identities, and distinguish independent native evidence from Burokrat observations. Implementing that boundary requires a separate `infra-evaluation-coverage` OpenSpec change, ordered TDD slices and R5 negatives for omitted YAML/extensionless paths, missing or corrupted authority, omitted registry modes and mismatched identities. This research does not implement it. The unresolved trusted `yaml` dependency is also a concrete blocker for evaluating the existing support TypeScript graph.

No host provisioning, live activation, native infra gate, production evaluator tests, deployment, certification or live WBS update was performed. The h2puni gate was not run: this documentation research ran on `pop-os`. Push remains withheld pending Astra review. These limits preserve the blocked WBS state and prohibit an infrastructure health or closure claim.
