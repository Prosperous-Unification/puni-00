## How to run a gate here without producing a number that means nothing

### Read this before believing ANY Playwright result

**A killed Playwright run exits 0 and prints a summary describing only the
fragment it reached.** Measured by the other session:

| Signal              | Value                             |
| ------------------- | --------------------------------- |
| Playwright planned  | **236 tests**                     |
| Numbered in the log | **67**                            |
| Printed summary     | `41 passed`, `1 skipped`          |
| NX                  | `Successfully ran target`, exit 0 |

A green exit code and a green-looking summary for a quarter of a gate. Neither
says anything about the 169 cases that never ran — R5's shape at the level of
the runner.

**The guard, and none of us was applying it:** compare `Running N tests using 1
worker` against the numbered cases and the summary before believing a result. If
planned ≠ run, the result describes a fragment. This retroactively casts doubt on
any interrupted gate in this repo, including some of both sessions'.

**A disproved diagnosis, so nobody re-adopts it:** an agent concluded that
`bin/with-heavy-lock.sh -- … nx run fe-01:e2e -- <file>` silently drops the file
filter, and recommended calling `bunx playwright test` directly instead. **That
is wrong.** `with_heavy_lock` consumes exactly one leading `--` and forwards the
rest untouched; the filter works through nx, verified by argument probe and by a
two-file run executing 43 tests rather than 236. The observation was real, the
mechanism was invented — and a wrong mechanism is worse than an unexplained
observation, because the next person stops looking.

- **The `$WBS_HEAVY_LOCK` override does not exist.** It was deleted because a
  caller that can choose its lock path can opt out of the lock. Setting it is a
  no-op. Use `bin/with-heavy-lock.sh` plain.
- **Serialise browser gates.** Two suites on one shift produced a 229/4 that was
  discarded. The clean serialised run is 232/4.
- **`E2E_PORT_SHIFT`**: shifts must be >100 apart and clear of the host's own
  listeners. **1700 is broken** — fe-01 lands on 5900, macOS Screen Sharing,
  invisible to a user `lsof`. I used **1900** (be 5000, gw 5100, fe 6100).
- **Check a PID is yours before killing it.** `kill $(lsof -ti :$p)` killed a
  neighbour's be-01 mid-run and produced 134 fictitious failures.
- **`tool-bootstrap`, `tool-devsync`, `tool-dagger` assert contention
  behaviour** and are uninterpretable beside another heavy job. My "quiet main
  baseline" of 53/7 and 26/2 was **not** taken on a quiet machine and should not
  be cited as a figure.
