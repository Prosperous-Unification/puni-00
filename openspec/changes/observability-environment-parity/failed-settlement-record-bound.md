## Why the finite-progress multiplier fails

The relevant source chain is:

1. Buffered writeback calls `ext4_map_blocks` with CREATE, METADATA_NOFAIL and IO_SUBMIT; the selected `dioread_nolock` profile adds UNWRIT_EXT. These flags do not request NO_NORMALIZE. [inode.c:2349–2397](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/inode.c#L2349-L2397)
2. For a hole, `ext4_ext_map_blocks` obtains regular-file blocks from `ext4_mb_new_blocks` before inserting their extent. A full inode-root extent array can require `ext4_ext_create_new_leaf`, which calls `ext4_ext_grow_indepth`. Sixteen potentially fragmented logical blocks are enough to require root growth; a 64KiB length cap does not exclude that branch. [extent insertion](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/extents.c#L2097-L2144), [root growth dispatch](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/extents.c#L1399-L1445), [allocation before insertion](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/extents.c#L4434-L4485)
3. `ext4_ext_grow_indepth` allocates a metadata block, calls `sb_getblk_gfp`, and directly returns `-ENOMEM` if the buffer allocation fails. That branch does not free its just-allocated metadata block and has not installed it in the root. [extents.c:1329–1337](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/extents.c#L1329-L1337)
4. The outer extent-insertion failure cleanup frees newly allocated payload blocks only for `-EDQUOT` or `-ENOSPC`. `-ENOMEM` does not enter that cleanup. This leaves allocation without successful logical mapping in the inspected path; it is not merely a callback-delayed free. [extents.c:4482–4506](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/extents.c#L4482-L4506)
5. The mapping wrappers propagate a negative return. `mpage_map_and_submit_extent` treats `-ENOMEM` as transient and can return it without setting `give_up_on_write`. `mpage_release_unused_pages(..., false)` unlocks the pages without invalidating their buffers. The writeback invocation then exits on `ENOMEM`; this is **not** an immediate infinite ENOMEM loop inside that invocation. But the dirty mapping survives for a subsequent writeback invocation, with no persistent attempt counter in these functions. [mapping propagation](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/inode.c#L602-L642), [transient classification](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/inode.c#L2477-L2517), [release without invalidation](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/inode.c#L1715-L1773), [writeback error exit](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/inode.c#L2949-L2989)

This identifies the exact missing causal factor, not a claim that a particular host exhibited a leak. For N repetitions of the root-buffer failure with successful preceding block allocation, the newly unreturned root blocks alone contribute `N * 4096` bytes; failed payload allocations are additional. `40961 * 4096 = 167776256`, exceeding 160MiB by 4096 bytes. There is no bound on N supplied by the fixed record count, record size, monotonic userspace write offsets, or the four-attempt fallocate theorem. This arithmetic is conditional on that failure sequence; no such sequence was injected or observed.

A finite physical filesystem provides a trivial ceiling on possible allocations. Charging the remaining filesystem as K would consume the required backing floor and is not a usable settlement admission theorem. Equally, a finite service deadline does not establish a number of kernel allocation attempts, and process termination does not establish successful drainage or invalidation of the surviving dirty inode. No assumed allocation rate or guaranteed syscall completion time is introduced here.

There is a second, distinct retry issue. For `-ENOSPC` with a journal, `ext4_do_writepages` forces a nested commit, clears the error and continues without a three-retry counter. `mpage_map_and_submit_extent` preserves dirty work when free clusters remain. Thus the old four-attempt multiplier does not apply even before considering ENOMEM. Successful progress is bounded by the file range; failed attempts are not equivalent to successful progress. The forced commit may reclaim prior frees, but its name alone does not establish a bounded simultaneously unreclaimed generation count under the accepted callback ordering. [inode.c:2484–2500](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/inode.c#L2484-L2500), [inode.c:2973–2982](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/inode.c#L2973-L2982)

## Exact prerequisite and predicates for a later closure

The first unresolved prerequisite is an independently reviewable guarantee that **every failed mapping either consumes a bounded per-operation attempt credit, or returns all of its blocks under a bounded peak-reclamation theorem**. A claim that allocation will not fail based on MemAvailable, the service memory cap, or initial free space is not an enforceable exclusion of the `sb_getblk_gfp` branch. ## Narrow publication alternative and finite partial bound

Requested follow-up: evaluate explicit native4KiB fallocate, aligned direct materialization and a final exact-length truncate, without changing legacy `raw.persist`, the record reader, raw-inode authority or the nine-file inventory. **Recommend interleaving allocation and initialization one block at a time**, rather than first leaving all16 blocks unwritten. This gives a structural reason why any buffered fallback cannot repeatedly allocate conversion nodes.

For each fresh exclusive metadata inode, let L be its complete in-memory canonical payload length and `R=ceil(L/4096)*4096`, with `0<L<=65536`. Captures must also be assembled within their existing bounded memory/byte envelope before publication; no live append transcript is part of this protocol.

1. Validate the exact original directory/slot and newly created inode's regular-file identity, zero initial length, same filesystem, EXTENTS profile, and absence of unsupported flags before materialization. This validation occurs after creation and therefore does not eliminate creation-hook cost.
2. For each next offset0,4096,...,R-4096, invoke exactly one native fallocate syscall, mode0, offset at the current end and length4096. No libc emulation and no application retry. Positive one-block allocation completes the entire call; ENOSPC has the already qualified four-attempt ceiling. Error stops this file and the operation; do not unlink or retry its partial inode.
3. Before writing, establish that the initialized prefix ends exactly at the current offset and that this newly allocated block is the only unwritten block, with no allocated extents beyond its end. Write exactly4096 bytes from an aligned buffer once using the qualified direct path. Its last block contains canonical bytes followed by zero padding. Reject short/error completion without rewriting the range. Successfully drain/verify this one block initialized before starting the next fallocate. Do not queue another block while conversion is pending.
4. After the last block, require a dense initialized map exactly on `[0,R)` and no extents beyond R. If `L<R`, perform one ftruncate on **this exclusively created metadata FD only** to L. Never truncate the raw inode; its descriptor remains read-only. No truncate is needed when `L=R`. Retain the original file-fsync then directory-fsync publication ordering, including the actual A/C return ordering and later durable proof/receipt.

The interleaving invariant matters on failure as well as success. Before a new block exists, all earlier blocks are initialized. The newly allocated unwritten block cannot merge with those initialized extents. There is no later unwritten suffix. An aligned block write therefore addresses the entire sole unwritten extent, whether the kernel uses direct I/O or buffered fallback. `ext4_split_convert_extents` takes its whole-extent branch and skips splitting; lookup/buffer-memory failure can postpone completion, but this mapping does not need a new payload or extent-tree block. Conversion can merge existing extents and free an already allocated node; those blocks were already charged at allocation. [whole-extent conversion](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/extents.c#L3826-L3897), [unwritten dispatch](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/extents.c#L3991-L4075), [metadata-node collapse](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/extents.c#L1871-L1906).

Preallocating all16 blocks and then initializing arbitrary subranges would not establish that invariant: a partial unwritten extent can need splitting, whose ENOMEM recovery may return the original error if zeroout recovery fails. This report does not replace that fact with a claim that O_DIRECT never falls back. The one-block interleaving is the smallest extra sequencing constraint identified here. [split failure recovery](https://github.com/pop-os/linux/blob/49748809f7e18ca62f2e054523f1e2c0eb7a88ad/fs/ext4/extents.c#L3473-L3527)

### Directory growth can be charged instead of assuming spare layout
