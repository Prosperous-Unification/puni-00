## Interfaces and ownership

- `open_staging_channel(state, nonce, request_digest)` acquires the original lock through `raw.acquire_staging`. It creates one close-on-exec AF_UNIX SOCK_SEQPACKET socketpair, enables SO_PASSCRED before enqueue, and sends exactly one canonical <=4096-byte transfer frame plus exactly its own locked FD as SCM_RIGHTS. No arbitrary FD or endpoint is accepted from a caller.
- Return an internal owned channel containing the parent control endpoint, recipient endpoint for a future Popen stdin and original locked staging FD. Explicitly closing the sender's recipient copy after launch must leave the parent control and staging descriptors owned. Closing owned descriptors never issues LOCK_UN. Any failed construction closes all acquired resources and throws.
- `receive_staging_channel(endpoint, state, nonce, request_digest)` borrows the endpoint and consumes exactly one already queued packet using MSG_DONTWAIT and MSG_CMSG_CLOEXEC. Absent/truncated/oversized/malformed packets, ancillary shape errors and extra/missing rights refuse without a retry. All received rights close on any failure; a successful returned staging FD is owned by the caller.
- The closed frame binds schemaVersion1, nonce, request digest, actual parent PID/start and UID/GID, plus canonical decimal device/inode and private0700 staging ownership. New native-width fields use decimal strings; existing historical metadata stays opaque.
- Authenticate the frame with kernel SCM_CREDENTIALS and fresh original PID/start. SO_PEERCRED on a parent-created socketpair identifies its creator and MUST NOT be mistaken for the eventual service worker. The received descriptor's original private directory/path identity, read access, close-on-exec state and actual fdinfo FLOCK ownership must join the original sender; an independently reopened same inode is not a valid transferred lock.
- Keep the packet and FD numbers internal to this Linux adapter. Receipt of a lock grants no raw-write, drain, reservation-credit or application authority. Do not add an acknowledgement/protocol variant, socket listener, retry loop, broker, general supervisor, dependency or persistent file.

## Why this transport

The selected installed systemd-run --pipe contract passes stdio descriptors as-is. A queued SCM_RIGHTS reference can therefore keep the same open-file description alive during service startup, before the service calls recvmsg. Parent-only or worker-only locks leave a process-death gap; releasing/reacquiring is unsafe. This slice proves ordinary-process transfer/queued-reference semantics, not actual systemd behavior. The selected systemd service handoff still needs separate native qualification before operational use. A future worker reply requires per-message SCM_CREDENTIALS joined to independently observed unit PID/start, not socketpair SO_PEERCRED.
