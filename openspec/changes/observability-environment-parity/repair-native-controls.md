# Bounded native repair primitive qualification

This is the next control plan, not executed evidence or repaired-disk acceptance. Execute only after its harness and exact source pins are independently reviewed, committed and freshly rebound. Task97, the actual repair and full two-instance observability acceptance remain open.

## Scope and prerequisites

Use only disposable owned tiny files and original owned child PIDs within one dedicated transient user service. Never open retained `disk.raw`, historical ISO, `/dev/kvm`, foreign writable paths or a host export. No guest, QEMU, download, mount, global flush or pressure replay. Reuse the committed worker's leaf functions and fixed geometry policy without changing production constants. Any fault is confined to the tiny owned control and explicitly named; controls with another policy layer omitted to avoid masking are labeled isolated policy witnesses.

Before starting, require exact current committed source/tool/runtime/kernel identities, complete retained-state plus outside-plan allocated-byte inventory, available memory and backing space. Charge every retained artifact, helper, fixture, certificate and future capture exactly once. Preserve 10 GiB retained staging, the 160 MiB outside allowance, 50/40 GiB initial/live free-backing floors and 2 GiB live host available memory; no floor changes. Additional native-control fixtures are capped at 2 MiB total allocated target bytes and all new control program/log/evidence metadata at 512 KiB. Inventory growth or unknown state refuses launch. Initial available memory must include the unchanged 2 GiB live reserve plus the 256 MiB service and three sequentially accounted 128 MiB outside actors: 2.625 GiB. This is launch headroom, not a larger service cap. Retained staging always includes the full fixed 160 MiB reserve independently of how much outside evidence currently occupies it.

## Finite service and controller

Dedicated nonce-derived `puni-repair-primitives-<nonce>.service`: MemoryMax256 MiB, swap0, CPUQuota100%/100ms, TasksMax32, RuntimeMax10s, stop1s, control-group kill, SIGKILL enabled, AS256 MiB, FSIZE2 MiB, NOFILE64, core0, umask0077, NoNewPrivileges, no restart. The separate controller has AS128 MiB, CPU5s, FSIZE64 KiB, NOFILE64, core0 and wall20s; per-pipe stdout/stderr64 KiB. A longer wait never silently raises these bounds. Effective native values and authentic counters must be observed, not inferred from arguments.

The worker holds the original staging flock across readiness, fixture creation, controls and the controller's durable completion ACK. Parent independently checks actual original worker PID/start/unit/InvocationID/cgroup and effective bounds before admission ACK. Controller records actual terminal state, exact owned group emptiness and independent repeated cleanup. Missing counter/ACK/exit/cleanup evidence keeps the control unaccepted; a D-state timeout initiates stop and never proves immediate reap.

All fixtures remain below the 2 MiB allocation cap. Do not create 4/8 GiB offset fixtures or repeat old geometry/pressure campaigns. Bound every fork/pipe/wait; at most one controlled child is live, with one additional child only in the clone fault. Native rejection must name the actual errno or protected-operation result; a Python wrapper exception is not a kernel denial witness. The full-chain positive and per-policy unmasked negatives have different scopes and are reported separately.

After the service is independently terminal, verify only declared fixture identities/contents, publish exact hashes, native effective bounds/counters, commands/exits/timing and remaining limitations in OpenSpec. Keep original failed guest/raw/ISO/history unchanged. This qualification does not release debt, accept a repair, certify a continued guest or close canonical3.1. Actual repair still requires reviewed v2 consumers, a fresh source-bound request and complete current admission.

Before helper import, execute only the verified repository source bytes, including transitive sibling imports; user-owned repository bytecode caches are not trusted. Root-installed system bytecode remains an explicit narrower runtime trust boundary. Inventory timestamps are part of every retained/outside entry except the exact padded request file, whose content SHA and original identity bind its deliberate in-place digest finalization. Enforce the 12-second controller/7-second worker work cutoffs immediately before every authority-granting ACK, first fixture write and publication, and bound subprocess observations by remaining work time. The hard 20-second limit and uncertain-cleanup refusal remain unchanged.

Request preparation, controller and worker use `LANG=C LC_ALL=C` so their actual runtime closures share the same locale. Installed Python startup hooks are limited to the exact `/etc/python3.12/sitecustomize.py` and `/usr/lib/python3/dist-packages/apport_python_hook.py` roles; root ownership, safe modes, source hashes and actual two-phase import closure remain mandatory. Nearby paths and declared-but-unselected hooks refuse before additional payload hashes.

Passive retained evidence/cache directories keep their recorded permissions. Inventory validates owned readable/searchable directory shape, refuses foreign owners/symlink traversal, charges every entry and binds all modification identities; passive inventory grants no payload execution or mutation authority. Active staging and control-packet directories retain their existing private-directory requirements. A refused, unfinalized padded request remains preserved on its original inode; only verified all-space preallocation may be finalized once after source correction, never an authorized/executed request.

Pin roles distinguish nonempty repository sources/executables from imported system runtime modules. An actual selected root-owned runtime module may have zero bytes (for example an empty Python package marker); root ownership, safe modes, original-FD identity/hash and exact actual runtime closure still apply. Source/tool zero lengths and unselected runtime declarations continue to refuse.
