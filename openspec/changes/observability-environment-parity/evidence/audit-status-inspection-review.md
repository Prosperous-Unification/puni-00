## Addressed finding

The initial bootstrap used compile(payload, path, "exec") and **file**=path. An uncaught error from output writing could make Python's traceback renderer reopen the mutable worktree path to display source after validation. This does not execute changed code, but privileged source rereading could disclose replaced file content and invalidated the no-reopen claim.

Proof: an isolated ordinary-UID /tmp fixture compiled an in-memory RuntimeError under the name of a file containing REPLACED_SOURCE_SENTINEL. Its traceback printed that sentinel; exit 1. The first fixture attempt had a quoting SyntaxError and supplied no evidence; the corrected fixture did. A separate synthetic-name fixture produced the expected exception with only <audit-status-inspection>, no filesystem source display. Neither fixture imported or executed the diagnostic or libaudit.

I subsequently reread the proposal and /tmp/puni-task116-audit-buffer-bootstrap.py. Both now use the literal <audit-status-inspection> for compile's filename and **file**. The reviewed diagnostic payload is unchanged. This resolves the finding without changing its native operations.

## Static safety assessment

- The bootstrap opens one final-component-nonfollowing descriptor, rejects nonregular/multiply-linked/empty/oversized input, bounds its read, checks exact bytes against the fixed hash, and compares pre/post descriptor metadata with current path metadata. It closes before compiling the captured buffer. Parent-directory symlinks are not prohibited, but cannot substitute different executable bytes under the fixed hash. Concurrent changes after capture cannot change the executed buffer.
- The privileged timeout owns a single Python child, with an outer five-second KILL deadline. There is no subprocess/controller/re-exec in the diagnostic. Python -I -B -S avoids caller Python paths/environment, bytecode output and automatic site hooks. Timeout does not cover sudo authentication; it is not a guarantee against uninterruptible kernel sleep. The one-second selector budget and four-frame loop are additional limits, not a proven hard one-second wall bound over every native call.
- The absolute library path requires a regular root-owned file without group/other write bits. Interpreter, standard library, loader, library dependencies and root-controlled ancestors remain ordinary trusted administrator inputs. The stat-to-load window is not independently pinned against concurrent root replacement, and the package/ABI evidence is a snapshot; this proposal expressly retains that trust boundary.
- The only libaudit entry points bound/called are audit_open, audit_request_status, audit_get_reply and audit_close. Exactly one explicit status request occurs after successful open. No setter, rules, registration, event API or group-subscription call exists. Successful open reaches one explicit close in finally; outer termination relies on kernel descriptor reclamation.
- Static objdump of the installed library corroborated audit_request_status sending type1000 with NULL/zero payload; audit_open only creates the netlink socket and sets close-on-exec, with no group join. audit_get_reply receives into the 8,988-byte embedded message, validates the sender's sockaddr PID as kernel, and writes the pointer union at the expected offset. This agrees with the recorded v3.1.2 x86-64 ABI and declared 9,016-byte Reply. The upstream sources were already cited in the facts; no new network retrieval was performed here.
- Error attribution is correct for the installed binary: audit_get_reply reads errno following recvfrom failure, retries EINTR, and negates errno before return (0x4b70/0x4c84/0x4cb7/0x4c6e). EAGAIN therefore returns -11, not -1. Using -received does not mislabel it EPERM. audit_request_status also returns its negative-errno status; audit_open uses errno separately.
- The parser checks minimum/declared length and request sequence, accepts only status or ACK/error, checks status size before copying 44 bytes, and never dereferences the native union pointer. Negative/positive netlink errors, short replies and unexpected types remain unavailable. The 65,536-byte cap covers serialized JSON, not all native-library stderr or interpreter diagnostics; no total process-output cap has been demonstrated.
- Explicit unavailable plus exit2 avoids treating denial or malformed input as disabled audit. Observed status plus exit0 establishes only receipt of status. The proposal clearly preserves unresolved consumer, rule/event, spool, allocation and quiescence facts and is outside the six-role runtime.

## Untested limits and required proof distinction

The exact wrapper and diagnostic were not run. No real audit negative/positive, timeout/cleanup behavior, native ACK ordering or successful kernel-status parsing was tested. Fresh source hash and static installed-library disassembly are evidence for this review, not behavioral tests.

For any future claim that the new guards are behaviorally verified, R5 requires focused negatives through the actual exercised paths: source mismatch/replacement and invalid metadata; absent versus unreadable input/library; library ownership/type and ABI mismatch; negative native return, timeout, mismatched sequence, truncated status, unexpected type/positive error and reply-count exhaustion; output-cap/output failure; and normal/terminated close ownership. These were not performed and must not be labeled passing. They can be exercised with controlled fakes where appropriate without repeating the denied real audit request. Their absence does not convert this narrow static operator proposal into production admission, nor authorize its execution.

Review tooling limits: the first login-shell read emitted unrelated dconf permission warnings; subsequent reads used login=false. A /tmp filename search returned exit2 for inaccessible private directories; those paths were not retried or used as evidence. No conclusions rely on absence from that search.
