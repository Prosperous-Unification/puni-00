## One-attempt consumption: a real unresolved boundary

K covers at most one call per fixed slot. An O_EXCL create may allocate, fail and leave no surviving filename. After process loss, O alone cannot distinguish never attempted from allocated-and-failed. A fresh nonce, pinned request, lock, empty directory, one-shot flag in process memory, preflight snapshot or hash does not solve this. Repeating failed preparation could accrue unbounded debt while charging K once.

Recommendation: source admission requires a separately qualified **durable consumption of the one fixed settlement grant before the first create**. It must be non-replayable across process/host loss and remain consumed even when publication leaves no name. This is not another settlement file, source role, operator budget knob or generic reserve service. Prefer an already authorized outer durable admission mechanism if root can identify one with an admitted finite allocation envelope. Its returned capability must bind original directory/inode,original reservation digest,request digest,new source pins and the single fixed nine-slot operation; no requested nonce can mint another grant. An old “unused” evidence file cannot itself be that mechanism.

No such mechanism is established by the three allowed plans or inspected source. Editing original failure/reservation, adding a marker/xattr, chmod, renaming or treating request creation as atomic consumption would change the reviewed physical/source contract and is not proposed. If no existing admitted durable boundary is available, Task113 must fail with a fixed `settlement-attempt-unqualified` category before first publication. Source fixtures may provide a finite controlled grant boundary and prove consumption/failure behavior, labelled as controlled external input; they must not masquerade as an operational implementation. Closing this prerequisite requires an explicit narrowly bounded design decision, not an approval question or fabricated successful receipt. This is the only remaining protocol decision not derivable from current source.

Likewise, once R is present it is not a resumable prepare/execute transaction. Prefer one coordinator invocation that publishes R then continues immediately. A process crash after any slot ends this fixed attempt. An apparently prepared request may be inspected but cannot restart a new allocator session.
