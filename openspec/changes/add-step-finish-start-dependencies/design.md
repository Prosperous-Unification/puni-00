# Design — step finish-to-start dependencies

## Model and validation

Store `{id, predecessor: {workItemId, scope: whole | step(stepId)}, successor: same, type: FS}` in a new typed-dependency table. Reserve a checked type field and endpoint/type uniqueness for B; only FS passes stage-A input validation. A leaf's whole predecessor selects its last slice finish; its whole successor selects its first slice start. A selected step chooses that leaf's matching slice. A parent expands to every descendant leaf, then every predecessor/successor leaf pair yields an FS slice edge. Keep the synthetic slice for a project without steps and offer whole scope only there. Unknown slices remain zero-time graph nodes; their two-day placeholder never becomes an endpoint.

Build the expanded authored graph with internal step-order FS edges and legacy `depReach` edges from `slice-edges.ts`. Detect cycles and self-slice pairs there, not at work-item level; refuse the edit without dropping any pair. Revalidate after reparenting, step reordering and endpoint edits. Refuse deletion of a referenced step until relationships are removed or reassigned. Legacy edges retain dynamic anchor selection until edited, at which point a single explicit FS relationship replaces the chosen legacy link atomically.

## Storage and deployment

Add a typed table with project, endpoint work-item IDs, scope discriminants, nullable step IDs, type, stable ID and a normalized uniqueness key for predecessor endpoint, successor endpoint and type. Enforce scope/step null pairing and same-project references at the validated write boundary; SQLite constraints/indexes back them where possible. Keep the legacy dependency table and read both. Ship an additive `migration.sql` beside `down.sql`; do not put destructive forward SQL in migration.sql. Deploy readers that understand both before enabling typed writes. Before rollback to a reader that ignores typed links, detect any typed rows and refuse rollback with a manual completion command or an explicit lossless conversion procedure; do not silently drop them. `down.sql` is for an authorized rollback after the guard passes.

## Command and document contracts

Keep `addDependency` and `removeDependency` request shapes and semantics intact for old HTTP/MCP clients. Add `addTypedDependency`, `updateTypedDependency` and `removeTypedDependency` as discriminators in the existing batch command union, retaining batch-local work-item references; do not require a new route or MCP tool. Address a stable relationship ID for edit/removal and carry explicit endpoints plus type on create/update. Use the existing batch runner and typed 4xx refusals; one committed edit is one undoable journal entry. Undo/redo must restore exact endpoints, type and identity, and refuse stale or conflicting state. Batch validation sees earlier writes. Generated OpenAPI and MCP batch schemas expose the new command variants while old clients remain callable.

Version plan document, export and saved-plan formats deliberately. New exports carry legacy and typed links distinctly; a legacy-format import preserves its `depReach` behavior, and a malformed new-format dependency is refused. Project copy and subtree duplication retain internal typed links with remapped IDs, preserve external links under the existing duplication policy, and reject cross-project or dangling endpoints. Saved plans and snapshots capture the dependency set and endpoint interpretation at save time; later step/tree edits cannot silently reinterpret a frozen snapshot. Coordinate the format version with parallel changes before implementation.

## Scheduling

Resolve authored dependencies once at the domain graph seam. Fast accepts external FS edges into any selected successor slice, computes predecessor finish as start plus real duration, and retains zero-duration nodes. The CP-SAT request carries the same expanded FS slice edges and internal order edges. Keep legacy reach in the canonical input hash and add typed endpoint/type identity and resolved graph influence; bump the scheduler contract version to retire stale optimized rows. The quantized baseline and solver request use zero for unknown slices, Q=48 rounding for positive durations, and FS `end[a] <= start[b]`. Independent response validation checks every expanded FS edge again on materialized real offsets; no solver output can silently lose a relationship.

## Picker and chart

Retain the one-line Depends on chip strip and existing popover tokens. Opening the picker then clicking a search result commits Whole→Whole FS. A separate `›` Customize control opens a roughly 360px viewport-bound editor without writing; choose predecessor scope, this work item's scope and FS, with project-step order retained. Parent choices say “All descendant work items” and show the affected leaf count. Keep refused choices visible with a reason. A chip such as `[010 FS · Dev → Dev]` has a full accessible label naming both work items and scopes; its detail card opens the same editor. Saving an edit is one undoable command.

Arrow-key search navigation, Enter for default add, a keyboard-accessible Customize control, ordered Tab, Escape back to picker then cell focus, and live success/refusal announcements cover keyboard use. On mobile, use the same fields in a bottom sheet and full-width cards with touch-sized Edit/Remove. Draw FS from predecessor finish to successor start, using actual zero-time ticks for unknown slices; route around visible bars and placeholders with the existing orthogonal router. Hover/focus of chip, card or arrow highlights the same slices. Group collapsed-parent connectors by visible ancestor pair, type and endpoint scope, with count and proxy styling; relationships internal to one collapsed subtree show an internal-dependencies count instead of a self-arrow.
