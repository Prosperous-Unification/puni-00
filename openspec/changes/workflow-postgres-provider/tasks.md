# PostgreSQL implementation tasks

All checkboxes below are future implementation/acceptance work. This initial publication records the selected direction and existing feasibility evidence. Test filenames below name planned tests; they do not claim those files or passing cases exist.

## 1. Resolve private protocol prerequisites

- [ ] 1.1 Specify physical-store namespace, exact lock overload/key binding, bootstrap serialization and coordination with migration/transfer writers; publish the operation-by-operation guard/replay/clock-order map — acceptance: reviewed design plus `postgres/open-stores.db.test.ts`; negative: change or remove retained lock metadata between admission and locked reread and observe a trusted-state error before publication.
- [ ] 1.2 Specify the supported server topology, exact backend identity, observer authority and cleanup, finite lifecycle budgets and sticky failure; account for connection replacement and exclude or prove prepared/detached transactions and alternate pooling — acceptance: reviewed design plus `postgres/store-lifecycle.db.test.ts`; negative: observe an active transaction after client-close fulfillment and prove no false close success, then exhaust observation with retained causes.
- [ ] 1.3 Specify a versioned complete transfer envelope and writer-pause/import protocol — acceptance: reviewed design plus `testing/provider-transfer-contract.ts`; negative: omit a recovery/write history, original acknowledgement or artifact and reject capture before target publication.

## 2. Real PostgreSQL fixture, lifecycle and admission

- [ ] 2.1 Build an explicit real-server fixture with exact runtime/server identity, independent connections and strictly owned bounded cleanup — test: `postgres/fixture.db.test.ts`; negative: mismatch owner/container identity or fail terminal observation and retain state instead of removing an unrelated resource.
- [ ] 2.2 Implement synchronous close fencing, queued rejection, admitted drain and sticky bounded observed disposal — test: `postgres/store-lifecycle.db.test.ts` and existing production factory lifecycle census; negative: bypass fencing with a retained live connection, leave a server transaction active after client close, and fail native disposal. Preserve original causes and do not claim earlier P10 failures are resolved by normal close alone.
- [ ] 2.3 Implement explicit bootstrap/open with paired additive migration/down artifacts, complete ledger hashes, metadata/physical-schema checks and durable settings — test: `postgres/open-stores.db.test.ts`; negative: absent/malformed/unreadable trusted state, edited applied migration, weak WAL/commit settings, unlogged relation or disabled required constraint must throw on the real admission path.

## 3. Current semantic operation families

- [ ] 3.1 Ownership and immutable artifacts/manifests/run creation: acquireOwnership, renewOwnership, retainArtifact, readArtifact, retainManifest, readManifest, createRun — test: existing run-store, artifact-store, manifest-binding and clock contracts registered for PostgreSQL; negative: bypass live-owner/clock/integrity checks, corrupt an existing artifact and distinguish operationally uncertain nonjournaled calls.
- [ ] 3.2 Run reads and attempt/legacy outcomes: readRun, admitAttempt, recordExecution, commitOutcome, reconcileReceipt — test: existing admission, execution, execution-command, outcome-collision, receipt and edge contracts; negative: real failure after reservation/outcome/receipt half-writes, write-local-ID exclusion bypass, active-recovery interlock bypass, and competing last-slot admission.
- [ ] 3.3 Decisions: receiveDecision, consumeDecision — test: existing decision/signal and edge contracts; negative: bypass decision correspondence or capacity gating, inject failure between consumption and reservation, and verify unconsumed state after refusal.
- [ ] 3.4 Receiver authority: pinRuntimeScope, readRuntimeScope, stageRuntimeRequest, recordRuntimeAcceptance — test: existing runtime authority/request/receipt contracts; negative: deliberate digest collisions, long keys, cross-scope global command reuse, mismatched original receipt and real mid-transaction abort.
- [ ] 3.5 Claim/turn provenance: stageClaim, recordClaimAcceptance, stageTurn, readExecutionHistory — test: existing claim/turn/execution-history/preparation/dispatch contracts; negative: bypass the existing adapter-level write-ID exclusions or scoped guard ordering, then inject failures between coupled history/attempt writes.
- [ ] 3.6 Recovery: beginRecovery, stageRecoveryFence, recordRecoveryFence, resolveRecovery — test: existing recovery and recovery-dispatch contracts; negative: bypass a scope barrier, change original replay provenance, omit one closure consequence or inject an actual transaction abort, then independently reopen and compare the whole prior state.
- [ ] 3.7 Coupled writes: stageWrite, recordWriteAcceptance — test: existing write-store/write-dispatch contracts; negative: omit an obligation/receipt/capacity half, mix local/wire identities, or bypass verified receipt correspondence and observe the intended production assertion fail.

- [ ] 4.3 Prove rollback, server restart and uncertainty on both sides of COMMIT — test: `postgres/recovery.db.test.ts`; negative: retain identical driver error categories around different actual commit outcomes and demonstrate no blind retry, false absent result or premature capacity release. - [ ] 4.5 Enable validated explicit production PostgreSQL selection only after provider acceptance — test: `open-stores.test.ts` plus real open/bootstrap/reopen cases; negative: unsupported provider, malformed configuration or absent state cannot silently select SQLite or create a store.
