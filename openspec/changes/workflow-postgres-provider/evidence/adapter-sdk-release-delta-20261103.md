Standalone ACP cancellation has a real but narrower delta: `RequestOptions.stopWaitingOnCancel` can reject the local request immediately after sending `$/cancel_request`. Published implementation marks the pending response abandoned, retains it for matching/dropping the peer's eventual reply, and suppresses cancel-send rejection. The default still waits for the peer. This changes local waiting semantics; it does not observe physical cessation, peer compliance or cancellation delivery. No runtime behavior was exercised. [Exact SDK source](https://registry.npmjs.org/@agentclientprotocol/sdk/-/sdk-2.4.0.tgz), `dist/core/jsonrpc.d.ts:64–95`, `dist/core/jsonrpc.js:485–505`.

Two permission changes also deserve precise scope. Claude now checks native file-tool paths against canonical workspace/readable-skill roots and requires approval for unknown native tools and worktree transitions. ACP now conditions non-allow-all auto-approval on trusted reported locations, then rechecks cancellation generation. These are source-level restrictions, not proof that a selected native agent mediates all effects or satisfies PUNI policies. The ACP bridge manifest is unchanged and still pins its own ACP SDK `1.7.0`, distinct from standalone `2.4.0`. [Claude source](https://registry.npmjs.org/@ai-sdk/harness-claude-code/-/harness-claude-code-1.0.177.tgz), `src/bridge/index.ts`, `src/bridge/permission-paths.ts`; [ACP source](https://registry.npmjs.org/@ai-sdk/harness-acp/-/harness-acp-1.0.113.tgz), `src/v1/bridge/permission-locations.ts`, `src/v1/bridge/package.json`.
