## Goals / Non-Goals

Establish effective supervisor identity for the just-installed invocation while preserving the existing admission boundary. This packet implements only disposable startup experiments. No production service change or activation/adoption claim follows from its checks.

## Decisions

1. **Execution closure.** Keep one canonical constant Bun `-e` bootstrap used by unit generation and expected-argv comparison. Read the bundle once, hash that Uint8Array and return the same object from `Bun.plugin` onLoad. Use a dotted private relative specifier with onResolve redirect; the prior pinned-runtime spike found bare specifiers unsuitable. Explicitly call the bundle's exported decoder and entrypoint; `import.meta.main` is false. Read config once, hash that buffer, decode that buffer and pass the decoded value into startup without a second pathname read. Read/hash the executing runtime through `/proc/self/exe`. Scan the built single ESM bundle and refuse non-builtin residual imports; `--no-install` alone does not close resolution.

2. **Startup policy.** Candidate direct-Bun argv includes `--config=/dev/null --no-env-file --no-install -e <literal>`. Use an explicit trusted cwd. Remove startup injection and dynamic-loader environment before Bun exec. The measured inputs are cwd `bunfig.toml`, cwd `.env`, `BUN_OPTIONS`, `LD_PRELOAD`, `LD_LIBRARY_PATH` and `LD_AUDIT`. Tested `NODE_OPTIONS=--require`, `BUN_CONFIG=<path>` and `BUN_CONFIG_PATH=<path>` had no preload effect; do not invent a config environment API from their names. Global-home config probes here also had no effect in this invocation form. No result establishes that every BUN_CONFIG variable is inert.

   The spike proves a clean child environment plus explicit flags blocks measured faults; it does not prove a systemd unit environment policy. For the direct-Bun unit, start with explicit `UnsetEnvironment` entries for measured executable inputs and conservative `NODE_OPTIONS`/candidate config inputs; enumerate and verify permitted Environment/EnvironmentFiles/PassEnvironment/UnsetEnvironment and manager inheritance in the disposable unit round-trip slice. `Environment=` alone is insufficient. systemd has no assumed wildcard clear-all here. If this cannot establish the bounded startup environment, stop for design review rather than silently inserting an `/usr/bin/env` wrapper: that changes the canonical executable/argv, and loader input can affect the wrapper before it clears the environment. Linux loader/system runtime integrity remains a host trust boundary; `/proc/self/exe` is not a libc attestation.

3. **Boot report and readiness.** A host-private per-attempt directory/socket and fresh unpredictable challenge are distinct from the backend-visible public socket. Retain nonce handling entirely host-side; never place nonce in world-readable unit argv or public frames. After config admission, orphan sweep and public listener establishment, the supervisor answers the private challenge with a bounded closed report of nonce, protocol version and bundle/config/runtime hashes. Close/unlink invocation-owned private resources on completion; cleanup failure is reported. Authenticity comes from client-side kernel SO_PEERCRED, expected UID and MainPID, not report fields. Also connect to the public listener and authenticate its kernel peer before accepting the report. The public solver client must enforce its expected server identity before writing a start frame; transport of that expectation must be settled in its own slice, not inferred from the nonce payload.

4. **Effective manager anchor.** Resolve the named unit with typed D-Bus GetUnit, then decode closed Unit/Service property responses. Include ExecStart's executable/argv tuple, MainPID, InvocationID, effective UID, FragmentPath, DropInPaths, NeedDaemonReload, ActiveState/SubState and the startup-policy properties. Check exact expected executable/argv and admitted effective property values; file text and `systemctl cat` are not this anchor. Define stable identity fields independently from volatile timestamps. Snapshot before both connects and after both connects. PID/InvocationID instability discards all connected evidence, then retries the whole observation within a fixed absolute deadline; a new nonce belongs to each new observation attempt. Per-call timeouts consume that same budget. Missing/null/malformed properties, credential failures and unexpected effective config fail rather than default. Final installed hashes of all four payloads must match, still under the same edge lock, before reporting identity success.

## Risks / Trade-offs

Private readiness alone cannot authenticate a distinct public listener. Independent D-Bus reads are not an atomic snapshot; before/after convergence is required and cannot promise resistance to a hostile system manager. PID reuse is narrowed by InvocationID, live connections and bracketed observations. Active service plus existing socket is insufficient. `bun:ffi` still loads host libc; this design attests Bun's executable and captured application/config bytes, not every mapped library or a compromised kernel/user manager. A root/same-user attacker able to modify trusted manager/runtime state exceeds the cooperative deployment lock boundary.

## Migration Plan

Implement the unchecked TDD slices only after this packet's review. Keep existing external-dependency dormancy and existing installer failure semantics. Version any new private/public identity exchange explicitly and refuse absent identity support; never fall back to old active/socket checks. No production rollout is included here.

## Open Questions

The actual direct-Bun systemd environment projection and literal argv round-trip remain unproved. Public-client expectation transport and the exact typed UID observation must be proven in their named slices before production admission. These are implementation gates with refusal on failure, not permission to weaken the contract.
