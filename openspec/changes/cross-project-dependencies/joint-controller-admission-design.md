# Joint controller admission: proposed bounded design

This extends the existing cross-project change after reviewed current21 integration. It is a refusal prerequisite, not compatible active controller operation. Root must review/materialize and issue a fresh lease. Stable input is1dde5b2c; b3 current21 is concurrent WIP, not accepted source here. V5 graph grammar and solver behavior are dependencies, not redesigned.

## Decision and modes

Add `assertOrdinaryControllerAdmission(directory, mode: 'legacy' | 'required'): Promise<void>` to existing `lib/edge-policy.ts`, using current bounded policy capture/codecs and actual marker observations. This name describes a check, not a reusable permission object. Its internal inputs come from fixed call sites/owned test construction, not an environment permit or caller-provided readiness/transport/graph.

Keep `assertNoEdgeOwner` as the literal marker-only primitive needed by initializer and owner/readers. Do not silently turn every internal use into controller permission. Instead route the enumerated ordinary admission points explicitly through the joint check. `withEdgeAdmission` invokes the policy boundary inside its lock callback; use a call-time module import if necessary to preserve the existing edge-policy→edge-admission dependency without initialization effects. No new shared service or parser copy.

Legacy preserves the existing pre-policy state only when the **fixed policy leaf** has exact ENOENT and both markers have exact ENOENT. First validate canonical readable real state directory, existing regular canonical lock and identity. Do not catch an ENOENT from a missing parent, nested record or arbitrary failing operation as absent policy. A present policy is decoded once with the current closed codec; only ordinary is admitted. No attempt to turn active pointer/markers into ordinary absence. A dangling link, directory, FIFO, malformed UTF-8/JSON, unknown fields/phase, permission failure or required absence refuses.

Within the existing edge-lock interval: capture policy presence/bytes/descriptor/named/parent identity, observe both marker absences, independently close the same policy observation and marker absences, check canonical state/lock identities, then enter protected effects. A changed policy or parent refuses rather than becoming a replacement baseline. State/marker mutations by cooperating controllers use the same lock; this is retained readback, not a claim of atomic global observation against arbitrary hostile root. Existing direct pre-effect guards in swap.execute/sync and owner publication must use the same joint meaning rather than merely retaining an old marker check.

## Initial owner ordering (I2)

`withDependencyOwner` must stop using the current all-locks-first recursion for initial admission. The exact order is: (1) validate plan, layout directories, canonical state and distinct lock paths read-only; (2) acquire ONLY the existing edge.lock with `withExistingCanonicalLock`, without O_CREAT, truncation, holder writes or finally-clearing; (3) jointly admit legacy policy and both absent markers, retaining the opening policy presence/bytes/file/parent and edge identity in this invocation; (4) acquire poll, devsync and selected deploy locks in their existing deterministic order using the existing lower-lock implementation; (5) recheck the original admission observation and all retained descriptions immediately before pending publication, refusing changed bytes/identity or newly appeared state without recapture; (6) publish pending and enter the existing owner callback/lifetime machinery. There is no new terminal protocol in this batch.

Implement `withOrdinaryControllerAdmission(directory, mode, action)` in edge-policy.ts: capture/check actual joint state, call action with only an invocation-bound `recheck(): Promise<void>` closure, then expire that closure. It must refuse recheck after action settles. Owner calls this inside the existing edge interval, acquires lower locks inside action and invokes recheck immediately before pending publication. The closure retains actual opening observations privately; no caller-supplied snapshot or reusable ready token. The one-shot assertOrdinaryControllerAdmission uses the same capture/closing implementation. This is shared parsing, not a second policy grammar.

On an initial active/restoring/marker/malformed refusal, **no lower lock acquisition** occurs: missing lower paths stay absent, existing sentinel bytes/identities stay exact, edge bytes stay exact, pending remains absent and owner callback count is zero. If policy drifts after allowed lower-lock acquisition, lower lock effects may have occurred, but no pending publication/callback is allowed; report that distinction. Real contender fixtures verify edge exclusion during the checks and owner operation, and ordinary release afterward. Missing edge.lock refuses without creating it. Existing lower-lock ordering, owner state and expiry remain unchanged after successful admission.

## Real fixed reader and locks

- `--check-controller-admission-inherited=required`

Reject duplicates, combinations with config/preflight/service options, and any other value. These are proposed new flags; they do not exist in5b2c. They run only the ordinary check, never active graph verification, service startup or config reading. Select the fixed mode above at the caller, not from an arbitrary controller request. Neither form can admit an active policy.

In legacy mode that helper does not itself require policy today; preserve this primitive property. The inherited FD is the existing WBS_EDGE_LOCK_FD transport, not a new token. No caller callback supplies success.

Shell parent opens the existing canonical regular nonsymlink edge.lock read-only and obtains nonblocking exclusive flock, or validates the already inherited same open description. Remove shell `mkdir -p state`/`touch edge.lock` from admission. Never recreate lock/state to make absence look ordinary. For TypeScript ordinary controllers use existing `withExistingCanonicalLock` when acquiring a fresh edge interval; retain existing inherited validation when already inside it. Its no-create/no-holder-byte-write behavior is already implemented. Preserve lock order edge→poll/devsync→selected deploy. Direct exported mutating execute/sync paths must either enter this wrapper themselves or verify/reuse its actual inherited description for the entire operation; a void policy check outside a retained lock is not sufficient. Choose wrapper reuse, with one private body to avoid duplicate effects.

The installed reader child receives the same inherited description across shell/Bun hops (existing FD3 mapping where required). Parent waits its original completion; nonzero/signaled/spawn failure prevents effects. A pending or uncertain original child/read is never converted to success or used to drop the parent lock while proceeding. Preserve the existing process/pipe custody discipline, not a new timeout/retry framework. Shell direct invocation retains the inherited descriptor while it waits; do not detach it. No controller acquires the permanently held solver-runtime.lock, and current21 solver runtime must not acquire edge.lock.

Do not accept a staging reader or a checkout helper as the loader's authority. A fresh normal solver install still runs the existing staged hash/version/ordinary checks after its fixed installed-reader admission. Staged success cannot replace installed-reader admission. Hashes/readiness cannot manufacture first-install approval.

## Exact pre-admission effect distinction

Root's protected-write boundary concerns runtime/trusted state, installed files, candidate checkout/reset, existing candidate cleanup, restart and exposure. Allow only **invocation-owned inert staging** before that boundary: a newly exclusively created0700 real directory beneath a validated parent; no alias, existing destination, reused directory or trusted filename replacement; copied inputs remain unexecuted and do not become configuration. Existing byte/hash checks still run under edge.lock before consumption/publication. Cleanup outside admission is limited to that invocation's proven unpublished staging after known settlement, never shared snapshots, installed paths or uncertain work. A prior separate preflight is not authorization over later writes.
