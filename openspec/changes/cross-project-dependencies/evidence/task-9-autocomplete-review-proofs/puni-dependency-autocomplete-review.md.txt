## Findings

### F1 — P1: completing a token discards its explicit stable project binding

Locations: `apps/wbs/fe-01/src/components/wbs/use-dependency-search.ts:53`, `:59`, `:91`; `plan-columns/depends.tsx:974`; `dependency-draft.ts:57`.

The only selected project observation belongs to the active token. Appending a comma/space makes the new active token empty, clears `scope`, and passes no observation to batch resolution. The earlier qualified token is then rediscovered by mutable abbreviation. An explicitly selected stable project can therefore be silently replaced by a later holder of its abbreviation.

Mounted actual-table reproducer `REVIEW a selected stable project stays pinned after a trailing comma`: select project `remote`/PUNI, make discovery subsequently return `reused-project`/PUNI, type `PUNI.080.s1-dev,`, press Enter. The observed command uses `projectId: 'reused-project'`; the expected pinned identity is `remote`. The failure is an exact command-argument assertion, not a setup failure.

**Required seam:** preserve explicit token observations/coordinates across delimiter and new-token transitions. Active-query scope may reset, but it must not erase the identity of an earlier retained token. Bind observations to the actual token occurrence/source span and preserve them while that token is unchanged; an abbreviation-wide alias alone cannot represent two separately selected occurrences. Submit through the existing `resolveDependencyDraft` / `PlanCommands` path using the pinned stable ID. An address change may refuse or require explicit reselection; it must never rediscover and author against a new holder. Keep the existing bounded query and numeric-local rules.

### F2 — P1: remote Customize reuses the previous target's project state and offers its endpoints

Locations: `apps/wbs/fe-01/src/components/wbs/plan-columns/depends.tsx:1014`; `plan-cards.tsx:2344`; `remote-dependency-editor.tsx:36`, `:49`, `:58`; `use-dependency-search.ts:54`.

Unlike the local editor, both remote caller branches have no identity key. `initialProject`, `expectedRevision`, and manual endpoint choice state initialize once and survive a new selection. The remote choice builder filters only by workItemId, without checking the selected stable project.

Two actual-table probes establish the consequences:

- `REVIEW switching remote Customize follows the newly selected stable project`: open PUNI Customize, select OTHER in the still-open picker and open its Customize. Add remains disabled instead of loading the new project's endpoint choices.
- `REVIEW switching same-abbreviation remote Customize never offers the previous project endpoint`: open `remote`/PUNI Customize, switch to `other`/PUNI with equal opaque row/step IDs, open Customize, select an offered scope and Add. The command sends `projectId: 'remote'`, although the user selected `other`. The exact payload assertion fails.

**Required seam:** define/reset the editor instance by the selected scoped identity, including project and endpoint, and the observation lifecycle needed for revision/runtime changes. Ensure the lookup is explicitly bound to that selected stable project, never merely an initialized abbreviation prefix. Filter/validate offered evidence against both selected projectId and workItemId before it can be selected or written. Reset manual choice/default/revision state when the target changes; retain it only for compatible updates to the same target. Use the existing scoped endpoint editor and authoring conversion. Do not add another write path, synthesize a remote row, or use the abbreviation as identity. Cover distinct abbreviations, reused abbreviations, equal bare IDs, and revisions.

### F3 — P2: local Customize erases earlier unsubmitted tokens on successful Add

Locations: `apps/wbs/fe-01/src/components/wbs/plan-columns/depends.tsx:781`, `:1098`, `:1140`.

The success callback correctly strips the active token, but closing local Customize focuses the dependency input. Its unconditional `onFocus` reset replaces the entire draft with an empty string. Reproducer `REVIEW local Customize retains previous mixed tokens after successful Add`: type `999, 010`, Customize local 010, Add. The command succeeds, but the observed input is `''`, not `'999, '`. Earlier unresolved work is lost.

**Correction:** distinguish opening a fresh picker from returning focus to its existing draft. Preserve the current draft and stable token observations when restoring focus; success may remove only the submitted occurrence when it still matches the captured draft. Exercise local and remote success/cancel/back with earlier tokens and newer edits. Do not fix F4 by copying this destructive focus behavior.

### F4 — P2: leaving remote Customize loses keyboard focus

Location: `apps/wbs/fe-01/src/components/wbs/plan-columns/depends.tsx:1027`.

The remote `onCancel` only unmounts the editor. Its focused Back button disappears and focus falls to body; no dependency field regains focus. Reproducer `REVIEW remote Customize returns keyboard focus to its dependency input`: open remote Customize and activate Back. `document.activeElement` is body, not the dependency input. Escape, ArrowLeft and successful Save share this callback.

**Correction:** return focus to the originating dependency input/picker with the draft-preserving behavior required by F3. Test the actual caller and real `.focus()` behavior, not only a callback spy.

### F5 — P2: a current cancelled lookup has no visible outcome

Locations: `apps/wbs/fe-01/src/components/wbs/dependency-options.tsx:189`; `remote-dependency-editor.tsx:99`.

The hook explicitly returns `state: 'cancelled'`, but neither options view renders it. In the actual field, a current request returning cancellation removes Loading and leaves only unrelated local options or an empty list, with no explanation or current-query recovery action. Reproducer `REVIEW current lookup cancellation is visible in the actual field` drives the installed lookup feature through its real address port returning `{kind:'failure', failure:{code:'cancelled'}}`; the mounted cancellation-message assertion fails. Task 9.1 and the ruling explicitly require cancellation to be modeled as a visible current-query outcome. Aborts of superseded queries should continue to be silently fenced rather than shown over the new question.

**Correction:** render a distinct current cancellation state in the ordinary picker and Customize, with the appropriate deliberate current-query retry/reopen action. Preserve stale/withdrawn request fencing and the service's no-send-after-close behavior.
