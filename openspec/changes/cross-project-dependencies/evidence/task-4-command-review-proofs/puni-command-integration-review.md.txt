1. **P2 — permit ordered local restoration for typed updates as well as adds.** `libs/wbs/application/core/src/service/compensating.ts:505` (`restoredTypedAddressesOf`, lines 505–509).

   The scanner only adds endpoints from `add_typed_dependency`. A valid mounted local batch can create a replacement predecessor and update an existing relationship to that batch alias. The batch succeeds and undo succeeds. On redo, the new predecessor is temporarily absent because the selected direction will first restore it. The scanner omits the update endpoint, so `walkStack` marks it as defective, returns `409 stale_undo`, and follows the stale-entry discard path instead of replaying a valid command.

   Reproducer: create a local predecessor plus FS relationship to an existing owner row; then POST a batch containing `createWorkItem {ref:'replacement'}` followed by `updateTypedDependency` with `predecessor:{scope:'whole',workItemRef:'replacement'}` and the existing successor. POST bodyless undo, then redo. Fresh observed statuses: initial 200, update batch 200, undo 200, redo **409** with `{"error":"stale_undo","detail":"a local dependency endpoint changed or was removed."}`. Expected redo: 200. This does not depend on external activation.

2. **P2 — keep the local restoration exception when the same journal contains external revision metadata.** `libs/wbs/application/core/src/module/work-item/work-item.resource.ts:6811` (lines 6810–6827).

   The `external === null` condition disables the ordered local restoration exception for an entire journal entry. In a real admitted SQLite transaction, create a new local successor and add a relationship from an existing readable remote predecessor, collecting and recording both commands together. The forward transaction succeeds and undo succeeds. Redo then reads the absent local successor before its earlier `restore_subtree` applies and returns `{ok:false,reason:'not_found',detail:null}`. The scanner already recognizes this restore/add ordering, but the blanket external-metadata condition prevents its use. All SQLite tables remain unchanged after that refusal. Production external authoring is dormant, so this is a semantic checkpoint defect, not a claim of mounted external success.

   Expected: redo restores the local successor and the relationship under current owner admission, remote read authority, exact external revision preconditions and connected graph validation. No remote row is restored.
