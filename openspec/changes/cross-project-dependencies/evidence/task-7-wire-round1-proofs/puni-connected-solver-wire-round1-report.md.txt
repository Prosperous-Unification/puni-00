2. Before either request or prepared terminal, each objective passes the normative wire-5 connected schema plus cross-field key, ownership, occupancy, and booking checks. The real contradictory 10/9 window still returns a terminal; `budgetMs: 0` and fractional `originOrdinal` now throw as malformed trusted preparation. Nine distinct corruptions of a complete request are refused, including duplicate keys, offset mismatch, bad edge/owner, missing occupancy booking, and an out-of-horizon booking.
3. The Python request parser refuses nonfinite values recursively, covering non-JSON `NaN`/`Infinity` constants and valid JSON `1e309`, in fixed and occupancy evidence. Occupancy quantization compares the scaled value to the safe range before calling `math.isfinite`, `floor`, or `ceil`. This also handles arbitrarily large finite JSON integers: `math.isfinite(10**400)` itself raises `OverflowError` if called first.
4. The CLI catches a modeled `RequestRejected` from the solve/witness phase as exit 64 with empty stdout; later-stage infeasible exit 70 and model-invalid exit 71 paths remain separate. A valid fractional fixed placement still yields the boundary terminal; a bad declared feasible witness is refused without traceback.

The builder catches only `ConnectedBoundaryOverflow`, so unrelated stage-integrity errors are rethrown. Incoming, reference, and outgoing cases each assert the typed failure.
6. Permanent production CLI tests refuse unknown local/foreign boundary keys and a foreign owner inconsistent with the fixed endpoint. An active-boundary CP-SAT UNKNOWN still returns `unknown`; it is not relabelled boundary-infeasible.
