## Why no invented append-caused cycle

`StepService.addWithin` only appends a fresh final step. It does not reorder existing steps, supply estimates for the new step or allow existing typed endpoints to reference it. Collapsing each new final node onto its old final node maps every new workflow, whole-boundary and unestimated legacy-anchor edge to an old edge/path. A new cycle would imply a prior cycle. Estimate insertion similarly moves an anchor earlier or leaves it fixed; an earlier-to-successor edge was already reachable through the old later anchor. Neither operation can introduce the requested cycle from a legal acyclic baseline under these rules. They receive genuine positive scenarios here. The previously approved independent graph-consumer delivery faults remain their call-site invocation evidence; those are not mislabeled actual cycles. No reorder API or illegal persisted endpoint was invented.
