# Existing legacy-reader adoption

The selected existing host has Bun, reader, configuration and unit installed, but its reader predates policy checks and no policy exists. Neither first-reader preparation nor old-reader transition can legitimately admit it.

Add one explicit administrative adoption route, dry-run by default, selecting the exact target/account, original artifact pins, parent identities and new reader. Use the ordinary initializer and its original receipt, checking the selected state parent and exclusively created lock before policy publication. Retain that same lock while replacing only the reader and checking both new capabilities. Preserve original evidence, Bun, configuration, unit, parent modes and service process. Known refusals retain partial files and evidence without automatic retry; unproven original child settlement retains lock custody.

No activation, native owner harness, policy bypass, automatic rollback, service restart, Bun replacement or relaxation of either existing route belongs to this change. The reviewed design is recorded in `legacy-reader-adoption-design.md`.
