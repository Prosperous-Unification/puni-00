## Entry and authority

NEW public `activateInitialDependencyHandoff(supplied, deadline)` in `lib/dependency-initial-handoff.ts` accepts a closed request `{format:'initial-dependency-handoff',version:1,activation,runtimeLaunch}`. `activation` is decoded by the existing complete-dependency-activation v1 decoder, unchanged; `runtimeLaunch` uses the accepted V5 exact codec and independently prepared profile/hash meaning. This is input selection, not a readiness callback. The caller has independently authorized and selected the exact activation/installed artifacts; no new issuer or test-result boolean is created. Production entry constructs real current solver/Docker/product-metadata/authority transports using the existing activation entry pattern. No public ports/ready/restore-success argument is accepted. A separately named internal owned-fixture entry may use the existing concrete transport seams and actual children, never replace the producer or its context validation.

The entry establishes one finite original deadline BEFORE preparation; the existing decoder's600000ms upper admission ceiling remains. It acquires the real joint owner using the reviewed controller/owner boundary, then calls `prepareInitialDependencyHandoffUnderOwner` -> `consumePreparedDependencyActivation` -> `restoreSolverForPreparedParticipants` -> `restoreBackendAfterSolver` -> `restoreGatewayAfterBackend` -> `restoreSourceAfterGateway` -> `restoreParticipantPoliciesAfterSource`. The fixed initial preparation wrapper is new and shares the existing core; the remaining names are existing APIs. The new entry does not replace the existing fenced-only activateExcludedDependencies/activateCompleteDependenciesUnderOwner behavior. Every effect and observation remains under the same original owner/deadline. Initial request attributes all required producer SHAs honestly to the one initial source, as the existing decoder requires.

In dependency-participant-restoration.ts, mint a private WeakMap continuation keyed by the original finalized context ONLY after the actual participants-restored record and final inspectPolicyParticipants closing pass succeed. Proposed `completeInitialHandoff(context)` checks original consumed-context identity, owner and phase; reserves attempted BEFORE the first handoff effect; consumes the closure once. No constructor accepts records, a copied context, summaries, booleans or externally supplied inspect callbacks. Premature, copied, released, expired and second calls refuse; admitted failure is terminal. The closure captures the actual ready/policy/restored records, immutable first-running bindings, expected restored restart policies, original solver object and retained monitors. The closed policy summary remains evidence only. Preserve every existing policy effect and observer.

The public entry, not a user-supplied callback, drives the remaining sequence and returns the terminal closed summary. It releases only owned descriptors after settlement and lets the original owner outer finally close its actual lock descriptions. No start/restart/recreate, controller effect, ingress effect or arbitrary user callback follows successful retirement. An unknown child/read stays inside the original operation, retaining descriptors and locks; no Promise.race throw-through-finally.
