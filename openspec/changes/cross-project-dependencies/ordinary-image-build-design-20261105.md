## E. Setup/build ownership and outcome contract

Use a new ordinary-only setup ledger; do not reuse historical parent singleton or its grants. Reserve each fixed operation record **before** calling the actual API. A record contains closed label, kind, original returned Promise/value, separate observer, terminal outcome/cause and joined flag. Public builder wrapper should return its genuine private async body's original Promise, with immediately retained observer; do not discard the only parent-level observation.

Concrete sequence: validate pure descriptor/epoch; establish referenced passive fixture keeper; capture canonical root and source/config/dependency input observations; await16 actual source reads with their original observers; render/validate in memory; create fresh output root; write exact entry; call actual Bun.build once; join its original and observer; validate success/output/metafile; read each actual artifact Blob via its original arrayBuffer Promise; write entry bundle and bounded metadata via actual write/Bun.write originals; join those originals/observers; hash retained bytes; return the build-only record. Do not wrap Bun.build in an async forwarding function and call the wrapper Promise the original. Plugin callbacks use preloaded map/port contents and pure resolver bookkeeping, never import production modules.

Use a closed per-label operation budget with96 total setup records as the initial first-slice ceiling (16 source reads plus root/config reads, one mkdir/root, one entry write, one build, one entry Blob read, bounded metadata/artifact writes and observers; observers share their parent records). No loop extends the budget or automatically retries. Define fixed byte/count caps for candidate metadata/artifact and retain a bounded diagnostic on overflow; exceeding a cap is failure, never proof of successful build or closure. Concrete caps and actual byte sizes must be frozen in the builder review before build qualification; do not borrow historical measured sufficiency.

Bun.build `{throw:false}` success:false is an actual settled build failure, not UNKNOWN by itself. Preserve bounded actual build logs/cause and throw after joining all started operations; no partial built artifact. A synchronous API throw is a recorded no-returned-Promise failure. Unknown original/observer, unsettled operation, missing expected compiler outcome or late unresolved callback prevents next build/write/entry and retains the ledger/keeper. A reporting deadline cannot resolve/abort an original, clear its keeper or claim cleanup. Existing180000ms preparation/240000ms observer envelopes are maximum inherited design bounds, not new measured build performance.

Retire only the setup keeper after every started settleable original/observer has been joined and all created ordinary output ownership is accounted for. Successful build files are retained evidence, not deleted and called cleanup. Known failure may retain partial output paths explicitly; no best-effort recursive deletion hides a failed write. No actual image/native resources exist in this build-only phase. Unexpected compiler/process uncertainty remains a retained failed run, not a forced successful retirement.

Return a closed record such as `{format:'dependency-owner-ordinary-image-build',version:1,status:'built-unqualified',sourceEpoch,imageDigest,titleDigest,entryPath,entrySha256,metafileDigest,sourceObservations,appliedCuts,resolutions,setupOperations,unqualified:[...]}`. It is **not** OrdinaryHoldObservationV1 and cannot be consumed as a case packet or runtime admission. No caller-provided boolean or empty list can turn it into ready.
