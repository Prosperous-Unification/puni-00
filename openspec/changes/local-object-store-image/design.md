## Technical shape

A separate object-store version lock records exact binary URLs, SHA-256 values, signature URLs, public key provenance, BusyBox base, BuildKit builder, and Buildx client. The existing toolchain runtime role alone records the image name and final manifest; build inputs reject duplicate image identity. The host verifies binary bytes using minisign before passing a minimal context to BuildKit; the image has no network download steps. COPY assigns mode 0755. SOURCE_DATE_EPOCH and exporter timestamp rewriting normalize build timestamps. The exported Docker archive also contains an OCI index and manifest, following the fleet controller pattern.

The local manifest names the PUNI image by digest with pull policy Never. The backup lab builds and verifies the archive, imports it using k3d image import into the owned cluster, checks the imported release tag's exact target in each node's k8s.io containerd namespace, registers the repository digest alias, and checks the alias target before applying the shipped manifest. Direct import alone produced ErrImageNeverPull because it only registered the release tag; the explicit digest alias restored resolution. Repeated imports pass the same checks. Runtime proof records image IDs rather than inferring digest resolution from docker load. Production kustomizations exclude this manifest.

The general platform and fleet k3d profiles prepare the same archive before Flux bootstrap. Each committed platform server and worker server/agent receives verified digest registration; preparation failures propagate before controllers are installed. The app-only profile skips object storage. Existing memory/disk resource guards remain authoritative for real profile startup.
