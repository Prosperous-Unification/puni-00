# identifiers — steps-not-phases (slice 1.1)
#
# Every distinct token matching `[A-Za-z_]*[Rr]ole[A-Za-z_]*` in `libs/`,
# `apps/be-01/src`, `apps/fe-01/src` and `apps/mcp-01/src`, enumerated before
# any edit (design D1: the rename is done from this list, never from a pattern).
#
# Three dispositions:
#   rename    the domain word — `Role`/`role` becomes `Step`/`step`
#   aria      the ARIA attribute and the testing-library queries built on it —
#             a different vocabulary that happens to share four letters (D1)
#   physical  a SQLite table, column, index, check or migration-folder name —
#             the database is deliberately left alone (D2, `steps-schema-rename`)
#
# `role` and `Role` appear under all three headings because the same four
# letters are the domain word, the ARIA attribute and the physical table name.
# Those occurrences are separated by context, spelled out under `aria` and
# `physical` below; everything the two do not claim is the domain word.
#
# Re-taken after each merge with `origin/main` (last: `a4648e4`, 37 commits
# including `work-item-types`, `external-refs`, `estimate-triple-visible` and
# `gantt-resize-scroll`). Those brought no new token to this list: every
# `[Rr]ole` they carry is one of the ARIA or physical entries below.
#
# Three more things spell the old word on purpose and are not in the rename
# column, because they are not the domain word either:
#   - the OpenSpec change names `phases-ui`, `role-crud`, `role-columns-fold`,
#     `role-progress`, `schedule-on-item-role`, `dep-waits-on-first-role` — a
#     change records what was decided in the words of its day (task 2.2);
#   - this change's own name, `steps-not-phases`;
#   - the negatives written for it, which assert the old word is gone and so
#     have to spell it: `no rendered string says Phase or Role`, the `stale`
#     regexes, and every `Proof:` quoting an injected fault.
