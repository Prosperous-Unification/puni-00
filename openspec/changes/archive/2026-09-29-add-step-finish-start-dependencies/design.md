# Design — step finish-to-start dependencies

## Model and validation

Rebased on step nodes (`address-step-nodes`; memo `puni-plan/wbs-feedback-2026-09-26/step-nodes/design.md` §3). Store `{id, predecessor: Endpoint, successor: Endpoint, type: FS}` with `Endpoint = {scope: whole, workItemId} | {scope: node, workItemId, stepId} | {scope: descendant-step, workItemId, stepId}`. The wire carries a node endpoint as its step node ID; the store keeps the pair so foreign keys hold. Reserve a checked type field and endpoint/type uniqueness for B; only FS passes stage-A input validation.

Endpoints resolve to step nodes at the graph seam (`resolveStepNodeGraph`), which already yields `workflow` and `legacy` edges; this stage adds `authored` edges carrying their relationship ID. A whole leaf predecessor resolves to its last step node, a whole leaf successor to its first; a whole parent resolves every descendant leaf that way; a descendant-step selector resolves that step's node in every descendant leaf; a node endpoint is itself. Every resolved predecessor/successor pair yields one FS edge; distinct authored relationships whose expansions overlap stay distinct records, and only resolved constraints deduplicate, keeping every provenance. Under a stepless project only whole scope is offered, resolved to the work-item boundary. Unknown nodes remain zero-time graph nodes; their two-day placeholder never becomes an endpoint.

Default mapping ("sane defaults"): row-level Depends on is Whole→Whole FS; opened from a step cell it proposes node→node on the same step ID, never by name; node→whole enters the successor's first node; whole→node leaves the predecessor's last node. An explicit choice always wins, and a predecessor without the preselected step shows it unavailable.

Detect cycles and self-node pairs on the resolved graph, not at work-item level; refuse the edit without dropping any pair. Revalidate the combined graph after typed and legacy writes, reparenting, step insertion/deletion/reordering, project `depReach` changes, any estimate edit that changes a dynamic legacy anchor, and history or batch replay. Validate the resulting state atomically before persistence; a UI-only prediction cannot enforce this. Refuse deletion of a step referenced by a node or descendant-step endpoint until relationships are removed or reassigned. A first-child hand-down applies `address-step-nodes`' one-to-one step node mapping to node endpoints in the same transaction and journals it. Deletion wins over hand-up: deleting a work item removes the typed relationships whose node or descendant-step endpoints lie in the deleted subtree, as legacy links are removed today, inside the same undoable entry; the folded hand-up of facts carries no endpoints. A parent that becomes a leaf by move or deletion refuses the edit while a descendant-step endpoint names it, naming the relationships; whole endpoints follow the tree. No structural edit broadens or narrows an endpoint's scope. Whole and descendant-step selectors follow the tree dynamically. Legacy edges retain dynamic anchor selection until edited, at which point a single explicit FS relationship replaces the chosen legacy link atomically.

## Storage and deployment

Add a typed table with project, endpoint work-item IDs, scope discriminants (`whole | node | descendant-step`), nullable step IDs, type, stable ID and a normalized uniqueness key for predecessor endpoint, successor endpoint and type; ordinary SQLite uniqueness over nullable step columns is insufficient, so the key column encodes the scope. Enforce scope/step null pairing, leaf-only node endpoints, parent-only descendant-step endpoints and same-project references at the validated write boundary; SQLite constraints/indexes back them where possible. Keep the legacy dependency table and read both. Ship an additive `migration.sql` beside `down.sql`; do not put destructive forward SQL in migration.sql. Deploy readers that understand both before enabling typed writes, and drain older writers first: an older binary can reparent a leaf that a node endpoint names without remapping it. Before rollback to a reader that ignores typed links, detect any typed rows and refuse rollback with a manual completion command or an explicit lossless conversion procedure; do not silently drop them. `down.sql` is for an authorized rollback after the guard passes.

## Command and document contracts

Keep `addDependency` and `removeDependency` request shapes and semantics intact for old HTTP/MCP clients. Add `addTypedDependency`, `updateTypedDependency` and `removeTypedDependency` as discriminators in the existing batch command union, retaining batch-local work-item references; do not require a new route or MCP tool. Address a stable relationship ID for edit/removal and carry explicit endpoints plus type on create/update; node endpoints are step node IDs or, inside a batch, `{ scope: node, workItemRef, stepId }` for a work item created earlier in that batch, resolved in the transaction; step references are resolved through `address-step-nodes`' revision-bound resolver before submission. Use the existing batch runner and typed 4xx refusals; one committed edit is one undoable journal entry. Undo/redo must restore exact endpoints, type and identity, and refuse stale or conflicting state. Batch validation sees earlier writes. Generated OpenAPI and MCP batch schemas expose the new command variants while old clients remain callable.

Version plan document, export and saved-plan formats deliberately. New exports carry legacy and typed links distinctly; a legacy-format import preserves its `depReach` behavior, and a malformed new-format dependency is refused. Project copy and subtree duplication retain internal typed links with remapped IDs, preserve external links under the existing duplication policy, and reject cross-project or dangling endpoints. Saved plans capture the dependency set and endpoint interpretation at save time for immutable read/display; later step/tree edits cannot silently reinterpret the captured record. Working-plan snapshots make committed mutations visible to subsequent reads in the same admitted batch. This stage does not add restoration of saved plans. Coordinate the format version with parallel changes before implementation.

## Scheduling

Resolve authored dependencies once at the domain graph seam. Fast accepts external FS edges into any selected successor slice, computes predecessor finish as start plus real duration, and retains zero-duration nodes. The CP-SAT request carries the same expanded FS slice edges and internal order edges. Keep legacy reach in the canonical input hash and add typed endpoint/type identity and resolved graph influence; bump the scheduler contract version to retire stale optimized rows. The quantized baseline and solver request use zero for unknown slices, Q=48 rounding for positive durations, and FS `end[a] <= start[b]`. Independent response validation checks every expanded FS edge again on materialized real offsets; no solver output can silently lose a relationship.

## Picker and chart

Retain the one-line Depends on chip strip and existing popover tokens. Opening the picker then clicking a search result commits Whole→Whole FS. A separate `›` Customize control opens a roughly 360px viewport-bound editor without writing; choose predecessor scope, this work item's scope and FS, with project-step order retained. Parent choices say “All descendant work items” and show the affected leaf count. Keep refused choices visible with a reason. A chip such as `[010.dev FS → dev]` or `[010 FS]` has a full accessible label naming both work items and steps; a descendant-step chip shows `020 · all Dev (3)` rather than a single step reference; its detail card opens the same editor. Saving an edit is one undoable command.

The single search-result click and its highlighted Enter use `addTypedDependency`. The comma-separated number entry continues to use legacy `addDependency` for its partial-success batch behavior; existing legacy chips and `removeDependency` remain readable and removable. New typed chips use `updateTypedDependency` and `removeTypedDependency` by relationship ID. This preserves the older multi-entry gesture while making the ordinary one-result flow explicit FS.

Arrow-key search navigation, Enter for default add, a keyboard-accessible Customize control, ordered Tab, Escape back to picker then cell focus, and live success/refusal announcements cover keyboard use. On mobile, use the same fields in a bottom sheet and full-width cards with touch-sized Edit/Remove. Opening the picker from a step cell preselects that step on both sides. Draw FS from the resolved predecessor node's finish to the successor node's start, using actual zero-time ticks for unknown slices; route around visible bars and placeholders with the existing orthogonal router. Hover/focus of chip, card or arrow highlights the same slices. Group collapsed-parent connectors by visible ancestor pair, type and endpoint scope, with count and proxy styling; relationships internal to one collapsed subtree show an internal-dependencies count instead of a self-arrow.
