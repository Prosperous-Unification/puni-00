## Context

The previous optimization is already present: [change-aware CI](../change-aware-ci/design.md) preserves docs-only checks, affected module selection and conservative fallback. Main/manual/full host verification intentionally remains full. Increased [workspace](../workspace-gate-time-budget/proposal.md) and [browser](../separate-browser-setup-budget/proposal.md) budgets prevented premature timeouts; they are not evidence of a speedup.

[Shared delivery](../../../libs/shared/domain/delivery/README.md) supplies provider identities, provenance, performed/carried executions and bounded/partial timing summaries. Its attempt-start waiting is explicitly not scheduler queue waiting. The [GitHub reader](../../../libs/shared/adapters/delivery-github/README.md) supplies bounded public observations, with no durable history. Preserve version 1 and add a separate receipt/report contract rather than silently redefining its timing fields.

Dash's activation observation store is an authority for activation scheduling, not a generic CI/deployment history database. Dash review telemetry and Burokrat's `ElapsedReceipt` / experiment accounting already preserve failed/censored intervals and receipt linkage. Reuse those semantics and offer an export mapping for fully attributed intervals; do not force arbitrary CI runs into a priced trial or import Burokrat into the shared domain. No activation-store migration is needed for this slice.

The [planning evidence](../../../docs/findings/delivery-waiting-baseline.md) records historical examples and the limits of those examples. They motivate collection; they do not choose the fix.

## Goals / Non-Goals

**Goals:** An autonomous observation loop: discover work, retain receipts, update reports/findings, and evaluate linked fixes without UI visits or operator-triggered collection. Establish current coverage before making a speed claim. The existing Elastic/Kibana and Prometheus/Alertmanager stack is the normal observation surface. CLI inspection and offline replay are diagnostic interfaces to that loop.

**Non-Goals:** All non-goals and constraints in [intent](proposal.md) apply. This PR is a plan. Measurement implementation precedes an independently reviewable optimization. No auto-merge or live host configuration change is authorized by publishing these artifacts.

## Decisions

### Receipt and report boundary

Add pure receipt validation and report/comparison functions under `libs/shared/domain/delivery/src/`. Keep transport and filesystem code outside that module. A receipt envelope carries version, identity, scope, revision and optional parent run/attempt/execution identity, observedAt, source reference/hash, named phase, outcome, interval endpoints, basis, clock domain and coverage reasons. Unknown fields use explicit null/reason states. Intervals from one process also retain monotonic elapsed time; cross-source wall-clock deltas declare precision and clock assumptions. Do not fabricate a parent link from timestamps or a matching branch name.

A bundle is immutable JSON receipts plus a manifest of content hashes and the collection outcome. Validate once on import; reject malformed trusted bundles, duplicate conflicts, negative intervals and impossible scope joins. Safe reimport deduplicates exact identities. A new observation of an unfinished execution has a new observation identity but the same execution identity, so the reducer selects the latest consistent state instead of charging work twice.

Add a small Bun CLI at `tools/tool-devsync/src/delivery-timing-cli.ts`, with pure composition/report helpers in the same directory. Proposed commands are `observe`, `status`, `findings`, `collect`, `report` and `compare`; documentation must label them proposed until implemented. `collect` accepts a canonical public change reference or a declared host receipt directory and writes a new bundle. `report` and `compare` operate offline and produce JSON plus Markdown. CLI exit success means a valid report was produced, not that an improvement was proved: `comparison.verdict` is explicitly `improved`, `not-improved` or `inconclusive`. Invalid bundles exit nonzero.

Scope the initial collector to public GitHub and operator-owned host receipts. The observer discovers runs for explicitly enrolled repositories, including work without a WBS reference. Its proposed `status` and `findings` commands expose persisted, scope-filtered machine-readable output for operators and a future repair worker. It does not expose a new unauthenticated server endpoint. WBS organization authorization remains in front of any future integration, and existing external references can link a published, appropriately scoped report. No new progress or budget writes.

### Reuse the existing observability stack

The repository already defines the [platform observability path](../../../docs/infra/platform.md#observability): the OTel collector sends logs to `logs-puni.otel-<environment>` in Elasticsearch and remote-writes metrics to Prometheus. Kibana saved objects, Alertmanager routes, collector queue/drop/backlog alerts, and backup/retention policy already exist. Reuse those components; do not create a second telemetry backend, dashboard service, notification router or long-lived local analytics store. Repository configuration is evidence of intended wiring, not evidence that a particular live endpoint is available.

The domain model exposes telemetry publication and evidence-query ports without Elastic index names, PromQL, OTLP transport, credentials or host names. Dedicated adapters provide the first implementation:

| Concern                                                       | Existing destination / extension                                                                                               | Boundary                                                                                                                                           |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Timing receipts, collection errors and finding revisions      | Structured OTLP log events through `infra/platform/observability/otel/collector.yaml` into the existing environment log stream | Versioned delivery event kind and opaque receipt/finding identity; typed allowlisted fields, no raw argv/environment or arbitrary attributes       |
| Timings, observation freshness, backlog and outcomes          | OTLP metrics through the existing collector to Prometheus                                                                      | Bounded labels for configured source class/environment/phase/outcome; revision, PR, run, receipt and finding IDs stay in logs, never metric labels |
| Searchable timelines, findings and before/after evidence      | Existing Kibana object bundle at `infra/platform/observability/kibana/objects/`                                                | Add delivery views/panels using indexed fields; queries and links preserve authorized scope                                                        |
| Stopped observer, ingestion failure and actionable regression | Existing rules under `infra/platform/alerts/` and Alertmanager routing                                                         | Extend tested rules and reuse routes; no new recipient or secret; no per-tick notification spam                                                    |
| Baseline/report reconstruction and repair-worker evidence     | Read-only, scope-constrained Elastic query adapter returning shared receipts                                                   | Backend pagination, retention and query failures remain explicit; unknown coverage cannot yield a complete comparison                              |

Local observer state is operational: source checkpoints/leases, bounded outbound buffering, policy/baseline references and immutable bundles pinned for a declared comparison. Reports and finding caches are reconstructible views. Elastic is the shared searchable history; frozen bundles preserve the evidence used in a decision after normal backend retention expires. Do not retain an unbounded duplicate local history or introduce a separate application database for observability. Authoritative frozen comparison inputs must not be silently pruned with transient buffer files; record their retention budget and refuse new pinning visibly when full.

Implement a dedicated delivery exporter in the tool composition layer; the framework-free domain must not import the WBS-owned logger or a vendor SDK. Reuse existing OTel dependencies and reporting/redaction conventions where applicable, without making the tools depend on the WBS product adapter. The current filelog parser only lifts known WBS pino fields and only tails pod log paths: writing arbitrary JSON to a systemd journal does not establish delivery ingestion. The host observer must explicitly export through an approved existing OTLP route. No network export occurs while gate/deploy code holds its heavy lock; that path only emits local receipts.

Add a narrowly typed delivery field mapping alongside `elastic/settings/failure-fields.json` and apply it through the existing settings Job. Extend saved objects through the existing import Job. Preserve current ILM, mapping bounds, collector redaction, network restrictions, TLS/mTLS and exporter queue behavior. Delivery attributes must be sanitized before export because current body/msg redaction does not cover arbitrary OTLP attributes. Read-only evidence access must use an existing authorized role and scope enforcement; missing suitable access is a rollout prerequisite, not permission to use collector admin credentials or weaken isolation.

An OTLP acknowledgement proves acceptance by the receiver, not successful Elastic indexing or Prometheus scraping. Track source collection and backend publication separately: last collected, last export accepted, last queried/indexed receipt, and last metric observed. A fresh local heartbeat cannot hide an ingestion outage. Existing collector loss/backlog alerts remain active; add delivery-specific absent/stale series rules so the central monitoring stack detects a stopped observer or host. Keep a bounded retry buffer until indexed evidence is confirmed or an explicit expiry/loss is recorded; an OTLP acknowledgement alone must not discard the only retained copy. The existing collector has a documented hung-export timeout loss case, so include that fault as well as connection refusal. Reconcile by immutable identity. Derive metric aggregates from deduplicated receipt state rather than incrementing on each export attempt, and test that replay does not increment execution work or observation histograms twice. Backend raw event duplicates must reduce to one receipt identity; do not claim exactly-once transport.

A queryable receipt, matching Kibana fields, observed metrics and a firing/resolving test alert are required integration evidence. Collector acceptance alone is insufficient. An unavailable backend preserves delivery command behavior but marks publication/coverage degraded; it cannot certify a complete report or close a finding. Host-loss detection depends on the monitoring stack remaining available; retain the existing Watchdog route for monitoring loss rather than claiming the observer can monitor its own host failure alone.

### First adapters and observation points

| Source                                                                      | Read or emit                                                                                                                         | What it can establish                                                                              | Limits                                                                                                                |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| GitHub adapter                                                              | Existing change/check/run/attempt/job reads, retained job step timestamps and CI selection artifact when available                   | Verdict completion, per-job execution, setup/test phase spans and retry identity                   | Queue eligibility stays unknown unless a documented source actually supplies it; never use `updated_at` as completion |
| `bin/heavy-lock-lib.sh` and `bin/h2puni-gate.sh`                            | Local receipt on enqueue, acquisition/refusal and command completion; phase receipts around existing `h2puni-gate-steps.sh` commands | Actual host waiting, lock occupancy and gate phase duration                                        | Preserve FIFO, canonical lock path, checkout-under-lock and signal propagation                                        |
| `bin/dev-poll.sh`, `bin/dev-poll-sync.sh`, `tools/tool-devsync/src/sync.ts` | Target observed, attempt started, dependency/publication/restart phases where executed, hold/refusal, health proof                   | Poller delay after observed target, retry/recovery, deployment execution and exact-revision health | Latest-main polling can skip revisions; checkout/last-synced is not health proof                                      |

The initial per-target breakdown uses existing Nx/log artifacts only where identities and intervals are unambiguous. When a CI job reports only an aggregate Nx span, report that span and missing module attribution. A follow-up needs module receipts only if that uncertainty prevents selecting a fix; do not instrument every test case upfront.

Autonomous collection is required for acceptance, but never a prerequisite of `gate` or `pixels`. A provider-neutral observer tick uses source, checkpoint, telemetry-publication, evidence-query and clock ports. An initial systemd timer adapter invokes the pinned observer every five minutes for enrolled public repositories and local host spools; manual `collect` is only a diagnostic/backfill interface. Repository run discovery includes failures, cancellations, runs without jobs and work without WBS links. It does not depend on PR authoring activity or someone opening the Delivery panel. No webhook endpoint or new provider credential is required for the first slice.

Each tick has a 60-second total deadline, a 32-request shared HTTP budget, bounded bodies and a single observer lease scoped to its state directory, independent of the heavy-work lock. Individual GitHub reads keep the existing 30-second bound. Enrolled sources share a persisted round-robin cursor so one busy source cannot starve others. Rate-limit responses honor their retry deadline and bounded backoff without a busy loop; backlog and next retry are visible. Adapter discovery and collection fit that budget rather than multiplying it by source count.

Persist immutable receipts before atomically advancing the corresponding checkpoint. Restart replays an overlapping discovery window and reconciles all unfinished attempts; deduplication prevents repeated work accounting. Interrupted publication must leave either the prior complete manifest or the next complete manifest. A corrupt/missing required checkpoint stops that scope visibly; only explicit first-time initialization can start with empty state. Retention gaps remain recorded gaps. Initial backfill is capped at seven days and proceeds across ticks; older history is explicitly outside coverage. Artifact/log failures cannot be hidden as complete coverage.

Reuse the bounded tick, protected runtime and service/timer patterns in Dash's [observation service](../../../apps/twilight-structure/twilight-dash/cli/src/activation/units/README.md), with a separate delivery state directory and launcher. Do not reuse activation authority, tables or credentials. Systemd is the first scheduling adapter; core records and tick behavior do not name a host, vendor or runner. Install templates are reviewable artifacts, not a claim that the service is already running.

Host emission performs bounded local writes only, with no network under the lock. Use one file per immutable receipt and atomic publication; no shared journal writer lock. Retain a collection-error signal separately from delivery status. The emitter is optional to the delivery command, not optional to observability acceptance: absence/unwritability is an observable collection failure with tests, whereas trusted receipt import remains strict. Do not introduce third-party dependencies into the isolated deploy candidate bootstrap graph. Define a bounded transient spool (30 days or 100 MiB, whichever comes first), report the retained horizon and any expired unexported receipts, and export through the existing telemetry pipeline before expiration. Pinned baseline bundles have a separately declared retention budget. Interrupted processes without terminal receipts remain censored; do not infer success from process disappearance.

### Metrics and comparability

| Measurement            | Endpoints / interpretation                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Verification latency   | Identified revision's observed verification request to completion of its required verdict set; unknown start remains unknown           |
| Execution work         | Sum unique performed job/phase intervals; parent phases and children are alternate breakdowns, never added together                    |
| Execution span         | Earliest performed start to latest completion, including gaps; distinct from work                                                      |
| Host queue wait        | Actual enqueue to lock acquisition, or enqueue to timeout/cancellation with that outcome                                               |
| Attempt-start wait     | Existing delivery metric retained under its existing basis; cannot be relabeled runner queue                                           |
| Retry gap              | End of one identified attempt to start of the next; separate from execution                                                            |
| Deployment latency     | Exact merged revision timestamp to matching served-health proof; merge timestamp absent means unknown                                  |
| Poller / deploy phases | First target observation, attempt start, build/install/restart and health boundaries where known; nested/overlapping intervals labeled |

Use immutable context manifests: event, selection mode, target/test inventory digest, required-verdict contract, source/lock/toolchain, resource class, concurrency and cache mode. A comparison names the intended treatment and permits only its declared context differences. Same-workload replay is preferable; observational matched cohorts remain explicitly observational. A docs-only run is never a baseline for an application run. Separate first attempts and retries in display while keeping both in totals and outcome counts.

Start with five matched baseline/candidate pairs per chosen workload stratum. Predeclare the primary metric and a material-reduction rule before candidate measurements: median paired reduction must exceed both 10% of baseline median and twice the baseline median absolute deviation. This is an operational screening rule, not a statistical significance claim. Show every sample, sample count, spread, median and failure/cancellation/censoring counts. Fewer pairs, absent context, incomplete chosen intervals or unresolved censoring make the claim inconclusive; show descriptive measurements anyway. Do not print p95 from this small sample. Real-world deployment incidence may make five matched pairs slow to obtain; report that limitation instead of generating gratuitous deployments.

Rank observed bottlenecks only within a declared cohort and coverage window. Do not add parallel job times or nested phases to claim an end-to-end saving. The optimization proposal must name which interval it shortens, its effect on other work sharing resources and the safety/test coverage that remains required. A changed workload invalidates the comparison unless separately stratified. A successful demonstration is an observed reduction with unchanged required checks and no worse observed failure/cancellation counts; insufficient evidence is a valid result.

### Autonomous findings and fix feedback

After each successful import, update the scoped report and export receipt/finding revisions to the existing stack. Publish queryable Kibana evidence and machine-readable scoped reports, with local diagnostic output available during backend outages. Retain a status snapshot with last tick attempt, last successful collection per source, coverage watermark, backlog, failure/backoff reason, heartbeat and next retry. A separate scheduled `status` check and readers compute staleness from their own current clock; after ten minutes without a successful collection the source is stale. Missing heartbeat is unknown/unavailable, never healthy. The inspector must run independently of the collection process and mark a failed/stopped collector visibly through service status and persisted findings. It has no merge or deployment credentials. The existing central Prometheus/Alertmanager rules inspect observed freshness and absent series independently of this host. A local timer alone cannot detect total host loss; end-to-end acceptance must demonstrate the central alert.

The scoped finding feed is the handoff to a repair worker: stable finding ID, policy/version, cohort/context identity, metric and affected phase, baseline/current values, sample/outcome counts, evidence references, coverage, first/last seen, and assessment. Assessments distinguish `needs-evidence`, `actionable`, `evaluating-fix`, `improved` and `not-improved`; observation gaps remain a separate finding kind. Evidence demonstrates a delay, not its cause. Repeated ticks update the same finding, and an unchanged evidence set does not count as another independent breach. No automatic issue/PR spam, code execution, work-item progress updates or fix application is performed by the observer.

A versioned policy declares metrics, absolute budgets, context matching and the comparison rule before evaluating observations. Missing policy or insufficient samples yields `needs-evidence`. Automatically assemble the first five complete compatible observations within the declared enrollment window into a frozen baseline, retaining excluded/censored/failed counts and reasons. This baseline supports regression comparison; an absolute budget can identify already-slow behavior. Never silently rebaseline to absorb a regression. Policy or intended workload changes create a new baseline identity and retain the old one.

Evaluate only newly changed evidence against that policy. Produce one actionable finding when the configured budget is breached or a complete matched comparison establishes a material regression; otherwise retain diagnostic rankings without asserting a fault. Observation gaps cannot close an existing actionable finding. Persist the baseline and finding before publishing the latest report so a crash cannot orphan its evidence.

A repair worker can read findings and register a proposed fix identity plus its baseline, treatment and success rule through an authorized local manifest. That registration does not authorize a merge or deployment. As normal candidate and post-merge/dev observations arrive, the observer automatically updates the comparison and finding, retaining `evaluating-fix`/`needs-evidence` until coverage is adequate. A merge, green CI or one fast run does not close the finding. `improved` requires the declared comparison and preserved checks/outcomes; failed comparisons remain visible. Automatic planning/code repair and policy-authorized execution are a subsequent bounded capability; this change supplies its evidence and feedback interface.

### Delivery sequence

1. Planning PR: intent, specification, design, tasks, retained historical evidence. No behavior changes. Await approval before merge.
2. Measurement PR: receipt/report model, autonomous observer, existing-stack exporters/query adapter/dashboard/alerts, host emission, deduplicated findings and automatic comparison, focused safety proofs and a real Puni report generated without a UI visit or manual collection. Can be prepared autonomously; installation/merge follows separate authorization. Preserve pre-instrumentation samples and measure observation overhead independently.
3. Optimization PR: select one bounded fix from the current report, open its own packet, preserve baseline manifests, and run the declared comparison. No preselected fleet/scheduler/test change. Record no-gain findings as readily as improvements. Await approval before merge.

## Risks / Trade-offs

- Read-only provider snapshots cannot reconstruct unavailable enqueue times or expired retry history. Missing evidence is a first-class output, not a reason to guess.
- Phase collection must not become the bottleneck. Measure five paired fixture workloads with emission enabled/disabled; flag added median wall time over 1% or 100 ms, whichever is larger. Production overhead remains unverified until observed.
- Host clock changes can invalidate cross-source elapsed values. Record source clocks/precision; refuse negative chronology and show uncertain cross-clock intervals rather than clamp.
- Private host paths or logs may contain sensitive values. Emit only allowlisted identities/phases/status/times, never argv, environment, headers or full logs; public exports require deliberate selection.
- CI/runtime cohorts change frequently. Preserve exact manifests and distinguish workload growth from a regression in execution efficiency.

## Migration Plan

No application database or version 1 API migration. Initialize separate versioned observer state and checkpoints explicitly. Add receipt files alongside existing operational state; never replace lock tickets or last-proven markers. Apply delivery mappings and panels additively through existing platform jobs. Verify the enrolled environment's actual OTLP path, storage, query authorization and metric/alert route before claiming rollout complete. Do not change secrets or activate production as part of this plan. Roll back collection by disabling its observer/emitter and reverting only delivery-specific stack configuration while retaining prior bundles; delivery behavior must remain unchanged. Deploy instrumentation and enable its observer/health timers on dev only after the measurement PR is approved and merged and installation is authorized. A disabled timer or unperformed restart/outage acceptance remains an incomplete rollout, not autonomous observation.

## Open Questions

No product decision blocks this plan. The baseline must resolve whether host queue contention, CI workspace execution, setup or repeated work dominates the selected workflow. The fix is intentionally not selected until then. Unknown provider enqueue semantics remain unsupported until verified against the provider's contract during adapter implementation.
