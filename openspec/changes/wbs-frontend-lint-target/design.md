# Frontend owner lint process design

## Entry point and ownership

The existing `apps/wbs/fe-01/project.json` target remains the entry point. Its single `options.command` keeps the existing 24 operand tokens in their current order, followed by the launcher’s literal operand delimiter. It invokes a small launcher in `apps/wbs/fe-01/tools/`. The existing `src/test-tiers.test.ts` extracts root operands from that string. Keep its omission proof and add an exact gate contract for the three directory operands and stable `lint:fast` command. The launcher and reporting module use `.mjs` to keep the tracked root TypeScript input list and all existing FE type configurations intact. The new `tools/tsconfig.json` inherits the FE spec options for the adjacent `.d.mts` declaration alone. This gives it a configured lint project while the Node test uses a real typed static import. Exercise their own root-config ESLint check explicitly. The minimal process contract tests can live in the existing FE Node-tier suite roster and must run in the normal FE Node venue.

The target runs from the workspace root. It continues to honor Nx's resolved orchestration behavior, including its inherited `targetDefaults.lint.cache`. Use `--skip-nx-cache` to demonstrate an actual complete run. ESLint result caching remains disabled for the full target. Keep the root config, policy discovery, full repository project graph, Node executable used by the installed ESLint CLI, lockfile and physical dependencies. Bun remains the repository launcher.

The suppressions file is a branch input to the FE target. In the FE `lint` target only, add `"inputs": ["...", "{workspaceRoot}/eslint-suppressions.json"]`. The pinned Nx array spread expands inherited target inputs. Confirm the actual resolved inputs before relying on this contract. If the effective project graph differs, retain every inherited input via an equivalent FE-only definition and prove the result. Compare actual ordinary task hashes for absent, present, changed and removed states without invoking four expensive lints. A present file must never share the absent-mode hash. A changed file must have a different present-state hash. Removal may reuse the original hash when the complete original inputs are restored. A full owner acceptance run still requires `--skip-nx-cache`. Disallow suppressions-state mutation while an active proof owns the source.

## Exact discovery and grouping

ESLint 10.10.0 exposes no public enumeration method that stops before lint rules. In one bounded adapter, use its installed `processOptions`, `createDefaultConfigs`, `createLinter`, `createConfigLoader` and `findFiles`, with `WarningService` and default CLI options. The read evidence documents their call sequence. Load these by absolute package path after resolving `eslint/package.json`, check the locked ESLint version and adapter contract, and fail on drift. Do discovery under the same Node environment and CWD as the normal lint CLI. A node-based coordinator launched from the Bun/Nx command avoids mixing Node and Bun config discovery. This adapter is a versioned toolchain dependency and does not implement its own glob engine.

Feed all 24 operands to the selector together. Existing explicit files are kept by the selector before ignore checks, so leave their ignored warnings to the same ESLint CLI. Directory results follow the original config traversal, including JS and applicable TS extensions. The discovered roster forms a pre-lint partition. Check normalized absolute path membership relative to the original operand and checkout, unique dispatch, nonempty required source and browser sets, and a total equal to the independent original selection in verification. Do not pass an empty argument list to ESLint, which can otherwise lint `.`.

Discover module directories from immediate child `tsconfig.json` files under `src/modules`, using boundary-aware path comparison. Keep direct files and children lacking that module config in the general `src` group. Include the two browser directories and 21 explicit root inputs in the browser/config group. The initial measured candidate has one non-module src group, one browser/config group, and deterministic small batches of module directories. Start with at most four module directories per child, sorted by module path, giving three module children for the ten current modules. Assign only starting file lists. Every child's imports, TypeScript service and Nx graph see the original workspace. Keep the original selector order inside each group and keep the group order deterministic. If a shared type context or workload still exceeds the approved profile, measure alternatives only under a new bounded decision.

## Worker protocol and output

Invoke the same installed ESLint CLI for each nonempty group with the exact selected files as arguments. Use argument arrays with no shell or glob expansion. Favor a tiny CLI formatter adapter that calls the installed default stylish formatter and writes one exclusive per-child coverage report through a private temporary directory. Confirm its supported formatter signature first. The report carries file paths and counts, no source contents. Forward normal stdout and stderr with bounded operational annotations. A missing, malformed or incomplete report after normal code 0 or 1 settlement is an integrity failure. Validate the exact path multiset from each reported group, with exactly one report entry per selected absolute path. The independent whole-CLI denominator remains a separate check. Preserve code 1 for ordinary ESLint findings and continue with the remaining groups to collect findings. Preserve code 2 for CLI configuration or usage failure and stop dispatch. Keep spawn, coverage-integrity and signal failures distinguishable from ordinary findings. A signaled close records the exact signal and yields the appropriate nonzero launcher status even when Nx later maps the task to its own failure code. A normal configuration failure may legitimately produce no formatter report. Keep the original status and diagnostic in that situation. An empty group never reaches the CLI. Release temporary reports once settled and retain sanitized proof receipts only in the verification venue.

Nx's run-commands executor currently forwards extra arguments by default. None of the tracked gate consumers inspected supplies ESLint flags. Model two invocation modes as a tagged union in the launcher and completion record. A default invocation enters serial mode. Arguments after that delimiter or a future root `eslint-suppressions.json` enter whole-CLI mode and print its reason. This passes the original 24 operands and trailing arguments to the single original ESLint CLI, retaining global flags and unused-suppression checks. This includes path-only forwarded arguments. Keep the delimiter out of the child argv and test the real Nx forwarding path. The exact target operands remain the documented interface. Whole-CLI mode cannot contribute a passing serial-target receipt, and missing or unreadable config, planner failures, child failures or resource pressure cannot switch modes.

Wait on child close, including pending stdio, instead of accepting spawn or an early exit event as success. Maintain one active child. On SIGINT/SIGTERM/SIGHUP, latch cancellation, forward to that exact owned child, prevent the next group and wait for settlement. The external guardian owns the total deadline and whole cgroup termination. Normal failure aggregation follows the installed CLI's ordinary lint failure versus configuration/usage failure classes. Native start errors and signal exits surface as failure. Record exact behavior from the old CLI in the first slice.

Nx's boundary rules can return without checking when the installed `project-graph-utils.js` writes `No cached ProjectGraph is available. The rule will be skipped.` to child stdout. The normal Nx target supplies the same full project graph and workspace-data path used by these rules. Preserve diagnostics while detecting the pinned warning across stream chunks and colour escapes, report which group was affected, and fail the serial execution even if the worker would exit zero. The final proof independently screens the complete raw streams for the warning. The warning does not rewrite the explicitly chosen whole-CLI compatibility status.

## Independent parity and measurement

Use a verification-only preload of the pinned ESLint helper to intercept `findFiles` from the **original CLI** and stop immediately after its real discovery returns. Its independently captured absolute roster must equal the union of the actual redesigned CLI formatter reports, including explicit ignored warnings. Missing/config-error scenarios use the ordinary old command to observe outcome. Compare a multiset of reported paths and normalize diagnostic rule ID, severity, file and range. Use future-file fixtures that cover a normal src file, direct module file, new module with config and unmatched directory. Add an ignored fixture and check warning versus discovery behavior in both commands.

For application, spec, each module project, browser and root overlaps, obtain flattened ESLint settings and the actual TypeScript parser project's config path, compiler-option fingerprints and selected fixture aliases. Use a small independent old CLI invocation on real representative paths and the real redesigned child invocation. The pinned ESLint implementation starts concurrent async file reads even with worker concurrency off. Record actual parser/project-service open order and the relevant preceding file context in each observation. Compare the actual selected Program path and compiler-option/ambient/alias fingerprints for each representative, including overlap controls and contrasting prefixes if selection is order-sensitive. Keep verification-only tracing outside production config. An unresolved Program difference or inconclusive ordering witness blocks qualification. Finder order, CLI argument order, config discovery and `tsc` outputs cannot establish which language-service Program lint used. Include cases whose types differ across configurations, such as Node/Vitest ambient types, a FE alias, e2e options and composite module sources.

Use one actual type-aware floating-promise sentinel and, in another real group, the established forbidden browser-adapter import or a named real product policy restriction. Require exact rule and path evidence from the normal Nx target. Reject any run that proves only the sentinels or only an individual group. See the proof roster in [tasks](tasks.md).

Capture child starts, PIDs, sequential closes and elapsed times with a local observer. Use the same qualified cgroup envelope and complete stream capture as the previous full-owner receipts. Compare whole-cgroup peak as the controlling memory metric, with per-child RSS and high-water observations explicitly labeled sampled. Measure total duration with discovery and startup. Acceptance requires the normal full command to return zero, complete selected and reported coverage, no forced stop or limit event, complete output, exact source binding and physical settlement within the approved profile.
