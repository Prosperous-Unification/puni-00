### Findings outside this change, not fixed

- Fixed on request (2026-10-07): inside `createWebsiteApi` the local request handler was named `fetch` and shadowed the global, so the default OIDC (discovery, token, JWKS) and legacy `/chat`/concept provider fetchers called the API itself instead of the network whenever `oidcFetch`/`providerFetch` were not injected, as in production. The handler is now `handleRequest`. Test: `server.test.ts` "without injected fetchers, OIDC discovery and the legacy provider call reach the network" (stubbed `globalThis.fetch` records the issuer's discovery URL and `https://openrouter.ai/api/v1/chat/completions`). Negative: naming the handler `fetch` again made `/session/oidc/start` answer 502 (Expected 302); it was red the same way before the fix. Rerun: be-01 test, lint, typecheck and build uncached (146 pass), `test:package`, `tools/tool-devsync` (391 pass) and Prettier all passed.
- The proposal card's brief field border was 1.91:1 against the card (WCAG 1.4.11 asks 3:1). No screens capture showed the card before; the new `build-paused` capture does, so the border now uses `--glass-line` like the composer.
- A 30 s stream deadline that fired after `api.close()` threw "Cannot use a closed database" into whichever test ran next once the be-01 and store suites ran past 30 s in one process. `markUnknown` now skips after close; startup recovery settles the same operation identically.

### Browser check solve times (slice 5.3)

Google Chrome 152.0.7977.64 headless on an i7-12800HX laptop, production build (`vite build` + `vite preview`), `PUNI_CHECK_ONLY=1 bun apps/website/fe-01/browser/conversation.mjs`, three fresh visitors per run, two runs each. The figure is the `puni-browser-check` performance measure: worker start plus solve, end to end.

| Difficulty                                             | Measured (ms)                    | Median  |
| ------------------------------------------------------ | -------------------------------- | ------- |
| normal, `maxnumber` 200,000                            | 248, 596, 202, 299, 760, 535     | ~415 ms |
| elevated, `maxnumber` 1,000,000 (fixture seeded $5.00) | 1869, 1338, 649, 2075, 878, 2650 | ~1.6 s  |

The normal difficulty stays well under 1.5 s, so the numbers are unchanged. The design's laptop estimates (0.1 s / 0.5 s) were about three to four times optimistic. The regular regression runs on the dev server recorded 444, 374, 118, 150 and 515 ms at the normal difficulty. Bun's own solver speed is 100,000 hashes in 134 ms and 500,000 in 677 ms.
