## Why

The WBS tool has no code yet — only an intent document (`init-spec-prompt.md`). Before any product feature work can begin, the repository needs a scaffolded foundation: a monorepo layout, a backend app, a dedicated WebSocket gateway app (adopted upfront so backend redeploys never drop real-time sockets later), a frontend app, a shared library, and a minimal deployment path. The stack is chosen in an **experimental-for-fun** posture (Bun, Elysia, ArkType, TanStack DB, etc.), so getting the foundation right now keeps that posture from bleeding into every feature change later.

## What Changes

- Introduce an **Nx monorepo — three top-level directories, Nx-all-the-way**: `apps/` (`be-01`, `gw-01`, `fe-01`), `libs/` (seven `@wbs/*` libs: `validation`, `domain`, `contracts`, `observability`, `config`, `realtime`, `scripts`), and **`tools/`** (nine `tool-*` Nx projects for infra: `deploy`, `dagger`, `compose`, `observability-stack`, `secrets`, `bootstrap`, `remote-scripts`, `git-hooks`, `smoke`). No free-floating `infra/`, `scripts/`, `dagger/`, or `secrets/` directories — every artifact lives inside an Nx project. Every workstation/remote operation is `nx run tool-<x>:<target>`.
- Add the backend application `apps/be-01`: Bun + TypeScript + ElysiaJS + Drizzle ORM (`bun:sqlite` driver behind a DB-agnostic repository interface) + ArkType for request/response validation. Organized as `controller → service → repository`; Drizzle types never escape the repository layer. **No WebSocket surface** on `be-01` — it is plain HTTP.
- Add the gateway application `apps/gw-01` (adopted upfront, not deferred): Bun + TypeScript + ElysiaJS. Terminates client WS (via Caddy upstream), authenticates on upgrade (JWT with env-injected signing key), maintains an ephemeral in-memory `subscription → sockets` map, forwards inbound client messages to `be-01` via internal HTTP, and exposes `POST /internal/push` for `be-01` to fan out server→client messages. **No DB** in `gw-01` — state is ephemeral; durable data (events, sequence logs for resume) lives in `be-01`'s SQLite.
- Define the internal `gw-01` ↔ `be-01` contract in `@wbs/contracts`: shared-secret `X-Internal-Auth` header, ArkType-validated payloads for `/internal/push`, `/internal/forward`, `/internal/resume`. Both services compile against the same schemas.
- Add the frontend application `apps/fe-01`: React, TypeScript, Vite, TanStack Router (file-based routing), **shadcn/ui via `@nx-extend/shadcn-ui`** (manual CLI fallback documented), TanStack Table, d3, and TanStack DB wired for two data modes: local-only (browser-persisted) and server-backed. In server mode the client talks HTTP to `be-01` and WS to `gw-01`; the reconnecting-WS client + resume-protocol state machine live in `@wbs/realtime`. Server mode is **not implemented** in this change — only the seams are preserved.
- Add a split deployment pipeline: **Dagger** (TypeScript SDK) owns build + test + publish (same commands run locally and on the deploy host, BuildKit-cached), producing versioned publish bundles for `be-01` / `gw-01` images and `fe-01` static assets. **Bun/TypeScript scripts using `Bun.$`** own the deploy step itself — ship the bundle via `ssh`/`scp` to a single Hetzner host running **Docker Compose** (services: `be-01`, `gw-01`, Caddy, plus the observability stack; `fe-01` served as static assets by Caddy), run a remote blue/green swap script, reload Caddy. A one-time POSIX `bootstrap.sh` installs Bun on the remote (the only `.sh` file shipped). No CI/CD platform, no Kubernetes. **Caddy** fronts TLS/ingress and proxies `/api*` → `be-01`, `/ws*` → `gw-01`. Dev-loop tooling (`nx serve`, `bun --watch`, `vite dev`) is explicitly out of scope for Dagger.
- Establish a **two-tier zero-downtime blue/green** deploy strategy:
  - `be-01` redeploys swap containers behind a Caddy upstream reload — **no WS impact** because sockets live on `gw-01`.
  - `gw-01` redeploys route new WS upgrades to the green instance while the blue instance keeps existing sockets alive through a drain window; clients reconnect via Layer-A resume (specced in the later sync-feature change, not here).
- Establish the DB-agnostic contract at the repository layer so swapping SQLite for Postgres later requires only a new Drizzle driver + repository implementation, nothing above.
- Ship the **Layer-A WebSocket resume protocol** end-to-end: per-subscription monotonic sequence numbers assigned by `be-01`, a bounded replay buffer (in-memory ring + durable SQLite `event_log`), a `/internal/resume` endpoint on `be-01`, reconnect-handshake handling on `gw-01`, and a client-side reconnecting-WS wrapper (with exponential-backoff + jitter, localStorage-persisted `last_seq` per subscription) in `@wbs/realtime`, plus a TanStack DB sync-engine adapter stub. Proven end-to-end with a single `ping`/`pong` message type; product WS message types land with their features.
- Ship **encrypted-at-rest secrets management** using [SOPS](https://github.com/getsops/sops) + [age](https://age-encryption.org) inside the Nx project `tools/tool-secrets/`: encrypted `src/*.env.sops` committed to the repo; age private keys on developer workstations only (backed up to password managers); a `.sops.yaml` at repo root listing recipient public keys; a pre-commit hook (part of `tools/tool-git-hooks/`) that rejects plaintext `.env` commits and heuristic secret leaks; `nx run tool-secrets:push` decrypts in-memory locally and streams to `/srv/wbs/.env` over SSH with `0600` perms. No plaintext secrets in git, no plaintext secrets on workstation disk.
- Ship an **Nx-native deploy pipeline** replacing all loose shell/bash scripts: `nx run tool-deploy:deploy [-- <tiers>|--all]` orchestrates the flow; per-tier deploys (`deploy-be`, `deploy-gw`, `deploy-fe`), bootstrap (`nx run tool-bootstrap:push`), smoke tests (`nx run tool-smoke:check`), and secrets push (`nx run tool-secrets:push`) are all first-class Nx targets. Change detection via `nx affected` against remote-stored last-deployed SHAs.
- Ship a **codified test strategy** optimized for agent-driven TDD (see design D20): layered unit / integration / contract / property / E2E / smoke / mutation; specific tool per layer (`bun test`, `vitest`, `fast-check`, Playwright, Stryker); 85% line coverage enforced on `libs/*` only; agent-done signal via `nx affected -t test,lint,typecheck`; 10 test-ergonomics rules written down.
- Ship a **lint + format baseline**: ESLint 9 flat config + Prettier 3 + lefthook (pre-commit); plugin set includes `typescript-eslint` (strictTypeChecked), `@nx/eslint-plugin`, `eslint-plugin-react`, `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y`, `@tanstack/eslint-plugin-router`, `@tanstack/eslint-plugin-query`, **`eslint-plugin-drizzle`** (enforces `WHERE` on DELETE/UPDATE), `eslint-plugin-unused-imports`, `eslint-plugin-simple-import-sort`, `eslint-plugin-unicorn`, `prettier-plugin-tailwindcss`. VS Code integration (`.vscode/settings.json` + `extensions.json`) shipped. Biome evaluated and rejected (no TanStack / jsx-a11y / drizzle peers).
- Wire **basic observability** from day one: `pino` structured JSON logging + `/metrics` Prometheus endpoints in `be-01` and `gw-01`, plus a self-hosted Grafana + Loki + Promtail + Prometheus stack running in the same Docker Compose as the apps. Minimal seed dashboards + a baseline set of alerting rules covering at minimum "service down" and "5xx rate spike" prove the pipeline end-to-end (exact rule list in design D14). Tempo / Sentry / Uptime Kuma / product-specific dashboards are deferred.

## Capabilities

### New Capabilities

- `monorepo-structure`: Nx workspace using **three top-level directories `apps/` + `libs/` + `tools/`**, project generation conventions, TypeScript project references + `@wbs/*` path aliases, Nx tag set (`scope:*`, `type:*`, `runtime:*`) driving `@nx/enforce-module-boundaries`, and build/test/lint orchestration across 3 apps + 7 libs + 9 tool projects. Every workstation/remote operation invoked through `nx run tool-<x>:<target>`.
- `backend-foundation`: `apps/be-01` skeleton — Bun + ElysiaJS HTTP bootstrap, Drizzle setup with `bun:sqlite` behind a DB-agnostic repository interface, ArkType validation pipeline, and the controller/service/repository layering contract. Includes the `EventSequencer` service, `event_log` table with retention job, and `/internal/resume` + `/internal/forward` endpoints backing the Layer-A resume protocol. No WS surface (WS lives entirely in `gw-01`).
- `gateway-foundation`: `apps/gw-01` skeleton — Bun + ElysiaJS WS bootstrap, upgrade-time auth with dual-key JWT validation (current + previous for seamless rotation), in-memory subscription map, inbound-message forwarding to `be-01`'s `/internal/forward`, and the `POST /internal/push` endpoint (shared-secret auth) for fan-out. Implements the reconnect handshake: receives `{type:"resume",resume_points}` frames from clients, forwards to `be-01`'s `/internal/resume`, relays replayed events through the normal push path, emits `resume_ack` / `resume_denied`. Proven end-to-end with `ping`/`pong`; product message types land later.
- `frontend-foundation`: `apps/fe-01` skeleton — Vite + React + TanStack Router bootstrap, shadcn/ui installation (Nx plugin path with manual fallback), TanStack Table + d3 wiring, and TanStack DB configured for local/server dual-mode operation (server mode as a seam; HTTP to `be-01` + WS to `gw-01`, neither wired to a real feature yet).
- `shared-libraries`: seven `@wbs/*` libs with a strict dependency DAG (no cycles) — `@wbs/validation` (ArkType foundation; DAG root), `@wbs/domain` (WBS business types + invariants), `@wbs/contracts` (HTTP + WS + internal contract schemas and resume-protocol message types), `@wbs/observability` (pino logger factory + log-field ArkType schema + pino serializer + metric wrappers + Elysia `/metrics` plugin under sub-path `/server`), `@wbs/config` (env + SOPS-decrypted-file loader + config schemas), `@wbs/realtime` (browser-only: `ReconnectingWsClient` + resume-protocol state machine + TanStack DB sync-engine adapter stub), `@wbs/scripts` (Bun-only: `Bun.$` wrapper + SSH builder + SOPS helpers + Dagger arg helpers for `tool-*` projects). Nx tags enforce boundaries.
- `deployment-pipeline`: an **Nx-native pipeline composed of `tool-*` projects**: `tool-dagger` (TypeScript SDK modules per app with `publish-{be,gw,fe}` + `publish-all` targets producing versioned `release-<sha>-<tier>.tar.gz` bundles), `tool-compose` (Compose + Caddy fragment templates + renderer), `tool-bootstrap` (remote host bootstrap — Bun + Docker + `/srv/wbs/*` tree), `tool-remote-scripts` (Bun-bundled `swap-{be,gw,fe}.ts` + `swap.ts` dispatcher running on the remote), `tool-deploy` (orchestrator + per-tier deploys; uses `nx affected` against remote-stored last-deployed SHAs for change detection). Caddy fronts TLS/ingress with routes `/api*` → `be-01`, `/ws*` → `gw-01`, `observability.<domain>` → Grafana. Blue/green semantics per tier (simple swap for `be-01`; drain-window swap for `gw-01`; atomic directory swap for `fe-01`). - `observability-baseline`: app-side instrumentation in `@wbs/observability` (pino structured JSON logging + log-field ArkType schema including `service`, `level`, `version`, `request_id`, `connection_id`, `user_id`, `ws_subscription`, `trace_id`/`span_id`; Elysia `/metrics` plugin via `@elysiajs/opentelemetry` + Prometheus exporter; gateway-specific metrics `gw_active_connections`, `gw_reconnects_total`, `gw_message_fanout_total`, `gw_drain_seconds`, `gw_inbound_messages_total`, `gw_backend_unavailable_total`; backend-side `event_log_rows_total` and `resume_replays_total`; OTel SDK initialized with traces exported to stdout in dev, dropped in prod until Tempo is added). ## Impact

- **Repository layout**: root becomes an Nx workspace with three top-level project directories — `apps/` (3 apps: `be-01`, `gw-01`, `fe-01`), `libs/` (7 `@wbs/*` libs: `validation`, `domain`, `contracts`, `observability`, `config`, `realtime`, `scripts`), and `tools/` (9 `tool-*` Nx projects for infra/scripting/deploy).
- **Tooling baseline**: introduces Bun, Nx, Vite, Drizzle, ArkType, TanStack (Router/Table/DB), **`@nx-extend/shadcn-ui`** + shadcn/ui, d3, Docker, Caddy, **Dagger** (TypeScript SDK + local engine container), `pino`, `@elysiajs/opentelemetry` + Prometheus exporter, **Grafana + Loki + Promtail + Prometheus** self-hosted stack, **SOPS + age** (workstation-only), **ESLint 9 + Prettier 3 + lefthook** lint/format baseline, **`bun test` + `vitest` + `fast-check` + Playwright + Stryker** test stack, and **ntfy.sh** (default) for alert delivery.
- **Developer workflow**: `nx` for the inner dev loop (build/test/lint/serve across three apps); `nx run tool-<x>:<target>` for every infra/deploy/smoke/secrets operation (no free-standing `scripts/` directory); a trivial top-level `bun deploy` alias for muscle memory. The only `.sh` file in the whole repo is `tools/tool-bootstrap/src/bootstrap.sh`.
- **Infra**: one Hetzner host running Docker Compose + Caddy with two Bun services (`be-01`, `gw-01`), static frontend assets, and a four-container observability stack (Grafana, Loki, Promtail, Prometheus). No Kubernetes, no pub/sub bus, no CI platform, no second-node contingency.
- **Architectural commitment**: `be-01` and `gw-01` are independent services with a versioned internal contract. Deploys happen per-service; cross-service changes need expand-→-backfill-→-contract discipline. This is a deliberate trade-off for cleaner redeploy semantics.
- **No product features yet**: no WBS domain behavior (no table, no estimates, no Gantt) and no WS endpoints. Those land in subsequent changes against this foundation.
- **DB-agnostic contract**: locked in at `be-01`'s repository layer — the `bun:sqlite` choice is reversible without touching services or controllers.
- **Forward-looking constraints preserved**: WS upgrades proxy transparently through Caddy; Layer A resume protocol is live and exercised by the `ping`/`pong` smoke test, so product WS message types add payload semantics without touching protocol plumbing; migration to a Redis/NATS bus for multi-instance `gw-01` only swaps the internal-HTTP call, not the client protocol; SOPS backend is pluggable so secrets storage can migrate to KMS/Vault without touching the file format.
- **Secrets workflow**: developers install `sops` + `age` locally, generate an age keypair, add their public key to `.sops.yaml`, and back up their private key to a password manager. Plaintext `.env` is forbidden in git; a pre-commit hook enforces this.
