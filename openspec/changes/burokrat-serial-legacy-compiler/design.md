# Design

The approved legacy-only runner uses five ordered phases: parse every config, collect imports, collect diagnostic strings, emit declaration membership, and resolve public surfaces in request order. Initial parsing captures root names, compiler options, configuration identity, project references and per-project transitive parsed reference commands, including known absence and cycles. Later phases reconstruct from those selections instead of reparsing a filesystem whose trusted packages materialize lazily. TypeScript requires each parsed reference command to retain its config-only JSON AST and config parse diagnostics; these small configuration records are explicitly allowed. No source-code AST, Program, checker, symbol, resolved-reference container or exception survives a project boundary. Operational diagnostics become strings immediately. Each phase replays its prerequisites on one reconstructed program. Synchronous Bun collection follows each helper return.

Parsing failures precede imports, imports precede diagnostics, diagnostics precede emission, and each public entrypoint resolves its owner and surface before the next. Failures propagate; there is no catch-and-defer mechanism. Diagnostic messages become strings immediately. The immutable materialized candidate and copied trusted closure supply every replay.

Only the filesystem wrapper changes routing. The bounded-source runner, compiler IO accounting, observation charges and finite limits retain their behavior. The existing source-admission loop is extracted at its identical call site for reconstruction reuse; every callback remains in its original order on the bounded path. Repeated legacy work trades execution time for lower retained memory; command receipts report elapsed wall time and sampled RSS. CPU user/system seconds are not measured. Legacy callers have no finite callback budget to reset or weaken.

The resource regression uses many configs sharing a generated TypeScript declaration surface and a unique public owner. The selected workload must finish under the recorded sampled process-tree ceiling after the change, fail with simultaneous retention restored, and produce the same complete report on a smaller equivalence workload. No blanket memory guarantee follows.

The original installed archive and consumer remain immutable. Hosted packaging produces a separately hashed successor; reports bind that successor, exact candidate commits and unchanged external policy bytes. Full surveys, CI and the canonical h2puni gate remain coordinator obligations.

## Collection placement follow-up

The unchanged real 21-config baseline with the separately identified SMTP-enabled package still exceeded 4 GiB during semantic diagnostics. Two isolated diagnostic copies preserved the original consumer and policy. All capture/import passes completed. An additional collection only before gateway diagnostics, after reconstruction and import collection, reclaimed about 609 MiB of reported heap while the gateway Program remained live; gateway then completed with zero diagnostics, and the next MCP configuration reached the same resource ceiling. Immediate post-helper RSS and Bun heap statistics do not establish exact object ownership: delayed allocation release and coarse counters are observed.

Keep existing post-helper collection and add collection at the same live-project boundary in observeDiagnostics and prepareEmission: after reconstructProject and collectImports, immediately before getPreEmitDiagnostics. This collects reclaimable preceding work before the next semantic allocation burst without changing source callbacks, configuration selections, phase/error precedence or the bounded runner. No config-specific branch or worker architecture is introduced. The earlier no-Program-retention invariant refers to application-owned references, not a promise that the runtime returns all pages immediately after a collection call.

The frozen baseline and unchanged policy supply the actual follow-up resource RED/GREEN workload under a 4 GiB sampled process-tree ceiling and 900-second deadline, with at least 12 GiB available. A dirty precommit package must be bound to its exact source patch and succeed within that guard before claiming this resource follow-up works. Remaining semantic refusals stay visible; process completion does not establish full acceptance. The measured workload is not a universal memory guarantee. Exact-commit installed acceptance and all five full reports follow separately.

## Public dependency collection boundary

The two-point pre-diagnostic candidate passed focused controls but its actual baseline still exceeded the guard during public emitted dependency traversal. The retained finer trace isolates a large allocation burst in a completed `schema.ts` dependency call; repeated uncached module-resolution manifest reads are present, but exact allocation ownership is not established. A targeted collection after that call was not reached in its probe. Moving that diagnostic collection before the call reclaimed preceding work while the current program remained live and allowed the complete diagnostic report under the unchanged guard. Its path-specific instrumentation is not production acceptance.

The approved generic candidate retains the two pre-diagnostic calls and adds one collection per legacy public entrypoint after semantic dependency discovery returns and before emitted dependency traversal begins. The internal `publicDeclaration` function accepts an optional `collectBeforeDependencies` callback at that exact boundary; only the serial caller supplies synchronous Bun collection. The bounded caller continues its four-argument invocation, with no callback, source-read, charge or failure-order change. There is no path branch, per-declaration collection, resolution cache or new lifecycle framework. This earlier boundary is not proven equivalent to the targeted probe: allocations between closure start and the measured schema call must still fit. Actual uninstrumented installed full-baseline GREEN and exact JSON equality with the successful diagnostic report are required before claiming this candidate works.
