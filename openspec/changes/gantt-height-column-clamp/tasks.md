## 1. The containment assertion, before the fix

Written into the test beside the assertion, and into `verify.md`.

## 3. The panel can give space back

## 4. A remembered height is re-clamped, not rewritten

- [x] 4.1 The panel re-clamps a remembered height against the current column on mount and on resize; the stored value is left alone — test: `a height dragged in a tall window is clamped in a short one`, `a wider window gives the dragged height back`; negative: the re-clamp writing back to storage, watched failing on the second case. Both tests are written into `e2e/gantt.spec.ts` and run 2026-08-30. The named negative — `setGanttHeightPx` + `rememberGanttHeight` on the measured room, inside the layout effect — was watched failing on `the chart did not get the dragged height back · Expected: 425 · Received: 225`, and on `- "425" + "225"` in the first case's stored array. **One honest hole is recorded rather than papered over**: with `appliedGanttHeight` taken out altogether and the raw claim passed down, `a height dragged in a tall window is clamped in a short one` was watched **passing**, because the panel's `max-height` is the same measured room and contains it either way. The re-clamp's separately observable half is the claim it leaves alone.
- [x] 4.2 The room is re-measured when a **child** of the column changes height, not only when the column does — test: `re-measures the room when the toolbar wraps under a new control`; negative: the per-child `observe` loop deleted. **New slice, found by running 1.1's assertion at other widths.** At 768×900 the toolbar is one row until the drag is committed, at which point `Reset layout` joins it and takes it to two; the column is `flex-1` in a window-tall page so its own box never changes, the `ResizeObserver` on the column alone never fired, and the panel's bottom landed at **904 against a column bottom of 892**. The test was written first and watched failing on the shipped code (`Expected: <= 893 · Received: 904`), then again with the fix's own loop deleted. Sixteen lines in `wbs-table.tsx`, all inside the existing layout effect.
