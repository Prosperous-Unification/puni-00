# Design

## Existing boundaries

Based on `main@87a2b7edbfaabae889d91daa823f16f520a51cec`. `DomainResolver.lookupTxt(name, signal)` in `libs/wbs/application/core/src/ports/domain-challenges.ts` returns one string per TXT record and throws on failure. `domain.routes.ts` already supplies a five-second deadline and maps lookup failure to `503 dns_unavailable`; it checks the captured claim again in the transaction. `apps/wbs/be-01/src/boot.ts` currently constructs the repository without a resolver, selecting its explicit refusing implementation. The retained-proof worker is callable only from the test harness; scheduling stays separate.

The design exercise combined brainstorming, grilling and domain modeling under the coordinator's authorized scope. Existing glossary terms suffice; authoritative DNS and TXT records are general protocol terms, so no new product glossary entry is introduced. The unresolved technical choices below are implementation prerequisites, not claims of reviewed code or instructions to activate production.

## Composition and configuration

Add an infrastructure adapter owned by be-01, behind the existing core port. Keep packet transport, packet codec and address classification private to that adapter. Use one reviewed, pinned codec; before adding it, inspect its actual decoding limits and license and prove malformed-packet behavior through the adapter. No handwritten general-purpose DNS decoder and no shell executable dependency.

### Reviewed codec boundary amendment (2026-10-16)

Use `dns-packet@5.6.1` (MIT), with `@types/dns-packet@5.6.5`, owned by the be-01 adapter. Its high-level decoder alone is insufficient: it allocates section arrays from untrusted counts, loses embedded-dot label identity, and accepts NS RDATA extending past its declared span. The independently reproduced alternative `dns-message@1.1.1` also accepts cyclic pointers and excessive expanded names, so it is not selected. Dependency characterization is not an adapter safety proof.

A narrow structural framing/name validator is permitted before the selected codec; it validates only this adapter's supported wire shapes and does not replace the codec with a general DNS implementation. Before any high-level/header decode allocation, require 12–65,535 bytes, exactly one question and a sum of answer/authority/additional counts at most 256. Require raw question and RR CLASS exactly IN, with no mDNS bit masking. Permit only A, AAAA, NS, TXT, SOA, CNAME and DNAME record decoders, refusing unsupported types before dispatch.

Validate every fixed field and RDLENGTH against the packet span, every name's consumed bytes against its containing wire field, and the final cursor against the exact packet length. NS/CNAME/DNAME consume exactly RDLENGTH; SOA consumes exactly its two names plus 20 fixed bytes; A/AAAA consume exactly 4/16 bytes; each TXT character-string stays inside its RDATA. Require the codec's final consumed-byte count to equal the packet length too. No unchecked unrelated RDATA decoder runs.

Use the codec's escaping name form (`name.decode(..., { mail: true })`) and structural checks to preserve label identity. Authority-relevant names reject embedded dots, backslashes, non-ASCII and lossy text before ordinary packet decoding; comparisons normalize ASCII case because DNS is case-insensitive. SOA RNAME is mailbox-shaped: its first label may contain an embedded dot and printable ASCII mailbox characters, and is checked structurally without treating it as a host identity. It is never used to choose a destination or owner. Compression pointers must target label/root/pointer boundaries of prior completed validated names, not arbitrary bytes or incomplete names. Stage new boundaries until their name validates. Cap 128 pointer dereferences per name and 131,072 label/pointer visits per packet, with expanded names at most 255 wire bytes and labels at most 63 bytes, before full decoding. Preserve the library's own backward-pointer and expansion guards as another boundary.

Every added boundary needs a crafted-wire negative through the final adapter path and a watched guard-removal failure. In particular, excessive-count tests must prove high-level decoding was never called, rather than merely observing eventual rejection after allocation. Preserve exact source hashes and executable candidate repros as dependency evidence; they do not complete any implementation checkbox.

Use an optional, explicit `ORGANIZATION_DNS_RESOLVERS` setting: absence means the existing refusing resolver, a documented modeled disabled feature. A present value is a comma-separated list of one to three distinct IP literals, each using port 53; empty, malformed or duplicate entries fail boot. IPv6 literals are bare literals, not URLs; no hostname resolution, arbitrary port, search suffix or OS resolver fallback. Private recursive resolvers are permitted because this is operator-controlled configuration. No credentials occur in this setting. The existing organization/browser activation configuration remains independent.

Boot creates one adapter instance with immutable resolver addresses and passes it to `DomainClaimRepository`. No discovery/network work at boot. The adapter never runs while activation and existing route authority refuse the operation. Production callers cannot override transport, address classification or deadline from HTTP input. Local fixtures inject the transport at the composition dependency seam while executing the same adapter/codec and guards; they do not weaken production address policy to reach localhost.

## Resolution algorithm

1. Validate the requested absolute canonical owner as `_wbs-verification.` followed by an already canonical claim domain. Enforce DNS label/name length limits before I/O. The route remains responsible for claimability policy. Reject an already-aborted signal before opening a socket. Set one five-second maximum from call entry, shortened by caller cancellation; discovery, retries and TCP fallback share this budget.
2. Discover a zone by asking a configured recursive resolver for NS records at the exact owner, then successive ancestor names through the final non-root label. Recursive NS discovery is explicitly trusted routing input, not the TXT ownership proof, and does not require AA. Accept a positive NS RRset only from matching IN/NS records in the answer section at the exact queried owner, with NOERROR and no CNAME/DNAME substitution or contradictory records. Advance to the next ancestor only after a terminal negative: NOERROR without the requested RRset (NODATA) or NXDOMAIN, with a valid IN/SOA in the authority section whose owner encloses the queried name, no alias at the queried owner or an ancestor and no contradictory answer records. SOA-less negatives are unsupported even where DNS permits them. A NOERROR response with authority-section NS records but no SOA is a referral, not NODATA; neither its NS records nor additional-section glue can select an authority. Referral, incomplete/unsupported responses, SERVFAIL, REFUSED, malformed packets and timeouts do not mean absence; try the next configured resolver at the same queried owner and type, then throw if none supplies a supported positive or terminal negative. Never advance to an ancestor on an unresolved discovery failure. Each recursive exchange, including TCP fallback after matching truncated UDP, has a one-second attempt budget within the shared deadline; partial discovery packets are never interpreted.
3. Require a nonempty zone NS RRset of at most eight distinct canonical names. Resolve those names' A and AAAA records through the same configured recursive service with the same response rules as NS discovery: accept only NOERROR matching IN records of the requested type in the answer section at the exact queried owner, without aliases or contradictions. Address absence requires the same enclosing authority-section IN/SOA terminal negative; SOA-less negatives, referrals and incomplete responses try the next configured resolver for that same owner and type, then throw if unresolved. Reject a malformed set; skip a name only after both address families have validated terminal absence. An absent family may contribute no addresses when the other family has a supported positive answer. An unresolved family must not be silently dropped, and no authoritative TXT exchange starts until address discovery succeeds. Build a sorted, deduplicated list of at most sixteen eligible IP endpoints. Excess limits fail instead of silently truncating. No address is taken from unsolicited additional-section glue.
4. An eligible authoritative endpoint is a globally reachable unicast address. Use a reviewed, explicit IPv4/IPv6 special-purpose classification policy, with a dated source and tests; normalize IPv4-mapped IPv6 before checking. Refuse private, loopback, link-local, unspecified, multicast, documentation and other special-purpose destinations. Reject the discovery result if it contains a prohibited address, rather than dropping that address and treating the remaining set as complete. Connect directly to the validated IP on port 53, never resolve its name again. Empty eligible set throws. Explicit recursive resolver addresses are the only exception to this destination policy.
5. Ask endpoints in deterministic order for IN/TXT at the exact original owner with RD=0. At most one UDP exchange and, only if TC is set on a validated matching response, one TCP exchange to the same endpoint per attempt. Budget each attempt to at most one second and the remaining overall deadline; TCP uses the remainder of that attempt. A timeout/network failure/invalid response can advance to another endpoint while budget remains; no background retry survives completion. Accept the first complete authoritative answer; consistency across all authorities is outside this slice.
6. Every exchange uses an unpredictable transaction ID and validates peer, ID, response bit, QUERY opcode, exactly one matching question/name/class/type and packet boundaries. TCP additionally validates its length frame; reject trailing, incomplete or oversized payloads. UDP truncation is never interpreted as an empty/partial TXT set. The final TCP response must have TC clear. Compression loops, invalid offsets, malformed RDATA and packet/record-count bounds throw for that attempt.
7. The final TXT response needs AA=1 and either NOERROR or NXDOMAIN. CNAME/DNAME at the queried owner or a claimed ancestor, referral, missing AA, mismatched TXT owner/class, and TXT material only in authority/additional sections cannot establish proof. NOERROR returns the exact-owner TXT RRset; a negative NOERROR/NXDOMAIN returns `[]` only with a valid enclosing SOA and no contradictory answer records. Otherwise it is unavailable. Decode each TXT record's character-string fragments as bytes joined in wire order, then losslessly into strings; preserve record boundaries and token bytes without trimming/case folding. Invalid text encoding is unavailable, not replacement characters. An unrelated valid TXT value is returned and the existing route decides it does not match.

Authority discovery is not DNSSEC validation. AA alone does not authenticate a server, and explicitly configured recursive discovery remains part of the trust boundary. No output may claim cryptographic authentication, resolver unanimity or a deployed ownership proof. This is the existing DNS-control method implemented with explicit limits.

## Resource ownership and failure

One lookup owns its sockets/timers and confirms closure before publishing proof or ordinary failure. Bound packet size to 65,535 bytes and decoded records to 256 per packet; the codec must reject malformed offsets and cyclic compression before unbounded work. The adapter stores no cache or persistent state. Concurrent requests have distinct request state and cannot consume each other's replies. Faults are contextual errors without TXT content, addresses from client payloads, raw packet bytes or challenge digests in logs. The existing HTTP layer maps a lookup failure to 503 and unchanged persistence; valid absence maps through the existing mismatch outcome, not 503.

### Reviewed cancellation and cleanup amendment (2026-10-16)

The adapter uses a 4,900ms absolute settlement bound inside the unchanged five-second route guard, with network work ending by 4,800ms. Each attempt has an absolute hard bound of the earlier of start+1,000ms and the lookup hard bound; network work ends at the earlier of start+900ms and the lookup work bound. UDP and TCP share these timestamps. Caller cancellation immediately stops accepting bytes and requests closure, then awaits bounded cleanup; it does not publish proof.

Attempt work includes packet decoding, routing validation and TXT conversion through a private synchronous acceptance callback. Recheck the absolute attempt cutoff and cancellation after that conversion. Recheck the shared absolute cutoff and caller cancellation after the final await, immediately before publishing values; delayed timer callbacks and queued aborts cannot extend either budget.

On response, failure or abort, initiate close exactly once and join its acknowledgment until the earlier of now+100ms, the attempt hard bound and the lookup hard bound. An ordinary outcome publishes only after close acknowledgment. A thrown close or expired join is a terminal `DnsCleanupError`: no peer retry, no proof, and closure is explicitly unconfirmed. The adapter must not disguise this as an ordinary DNS timeout or assert a resource was closed when close failed. Cancel all owned timers on settlement; late callbacks cannot publish or retry. A bounded transport join also detects an injected transport that ignores cancellation. Generic race-first deadline helpers cannot own this DNS lifetime because their abort race can mask required cleanup failure.

## Follow-ups and external prerequisites

The implementation may finish task 5.2's adapter/composition sub-slice with local protocol and mounted evidence. It does not close the whole task or WBS row until controlled real-domain and activated lifecycle acceptance are recorded. Tasks 5.3–5.5 still need automatic worker scheduling. SMTP, organization activation inventory, production browser-authority enablement, migrations/rollback acceptance and other organization tasks remain separate.

Operators must choose recursive resolver addresses, permit bounded UDP/TCP port 53 egress, deploy configuration, control a disposable domain and authorize an attended real challenge/rotation/failure exercise. No such input is needed to implement and locally prove this adapter. An incompatible DNS deployment (aliases, excessive NS/address counts, only private authoritative service) receives an explicit unavailable outcome until separately designed support exists.

## Protocol references

The query/answer validation and TXT record shape follow [RFC 1035, sections 3.3.14 and 4.1](https://www.rfc-editor.org/rfc/rfc1035.html). Zone NS authority and alias restrictions are described in [RFC 2181, sections 6 and 10](https://www.rfc-editor.org/rfc/rfc2181.html). The distinction between referral and NODATA follows [RFC 2308, section 2.2](https://www.rfc-editor.org/rfc/rfc2308.html#section-2.2); requiring SOA evidence for every accepted discovery negative is a deliberately narrower supported response policy. These sources justify protocol requirements, not live acceptance or authenticated DNS claims.

Use the [IANA IPv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry/) and [IANA IPv6 special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry/) as dated classification inputs, together with multicast/unicast ranges. Their classification does not promise actual network reachability; that is observed by the bounded exchange.
