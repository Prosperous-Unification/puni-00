# Design

## Existing boundaries

Based on `main@87a2b7edbfaabae889d91daa823f16f520a51cec`. `DomainResolver.lookupTxt(name, signal)` in `libs/wbs/application/core/src/ports/domain-challenges.ts` returns one string per TXT record and throws on failure. `domain.routes.ts` already supplies a five-second deadline and maps lookup failure to `503 dns_unavailable`; it checks the captured claim again in the transaction. `apps/wbs/be-01/src/boot.ts` currently constructs the repository without a resolver, selecting its explicit refusing implementation. The retained-proof worker is callable only from the test harness; scheduling stays separate.

The design exercise combined brainstorming, grilling and domain modeling under the coordinator's authorized scope. Existing glossary terms suffice; authoritative DNS and TXT records are general protocol terms, so no new product glossary entry is introduced. The unresolved technical choices below are implementation prerequisites, not claims of reviewed code or instructions to activate production.

## Composition and configuration

Add an infrastructure adapter owned by be-01, behind the existing core port. Keep packet transport, packet codec and address classification private to that adapter. Use one reviewed, pinned codec; before adding it, inspect its actual decoding limits and license and prove malformed-packet behavior through the adapter. No handwritten general-purpose DNS decoder and no shell executable dependency.

Use an optional, explicit `ORGANIZATION_DNS_RESOLVERS` setting: absence means the existing refusing resolver, a documented modeled disabled feature. A present value is a comma-separated list of one to three distinct IP literals, each using port 53; empty, malformed or duplicate entries fail boot. IPv6 literals are bare literals, not URLs; no hostname resolution, arbitrary port, search suffix or OS resolver fallback. Private recursive resolvers are permitted because this is operator-controlled configuration. No credentials occur in this setting. The existing organization/browser activation configuration remains independent.

Boot creates one adapter instance with immutable resolver addresses and passes it to `DomainClaimRepository`. No discovery/network work at boot. The adapter never runs while activation and existing route authority refuse the operation. Production callers cannot override transport, address classification or deadline from HTTP input. Local fixtures inject the transport at the composition dependency seam while executing the same adapter/codec and guards; they do not weaken production address policy to reach localhost.

## Resolution algorithm

1. Validate the requested absolute canonical owner as `_wbs-verification.` followed by an already canonical claim domain. Enforce DNS label/name length limits before I/O. The route remains responsible for claimability policy. Reject an already-aborted signal before opening a socket. Set one five-second maximum from call entry, shortened by caller cancellation; discovery, retries and TCP fallback share this budget.
2. Discover a zone by asking a configured recursive resolver for NS records at the exact owner, then successive ancestor names through the final non-root label. Recursive NS discovery is explicitly trusted routing input, not the TXT ownership proof, and does not require AA. Accept a positive NS RRset only at the exact queried owner and reject CNAME/DNAME substitution. A validated NOERROR response with no such NS permits the next ancestor; NXDOMAIN likewise permits the next ancestor. SERVFAIL, REFUSED, malformed packets or timeouts do not mean absence; try the next configured resolver, then throw if none answers validly. Never advance to an ancestor on an unresolved discovery failure. Each recursive exchange, including TCP fallback after matching truncated UDP, has a one-second attempt budget within the shared deadline; partial discovery packets are never interpreted.
3. Require a nonempty zone NS RRset of at most eight distinct canonical names. Resolve those names' A and AAAA records through the same configured recursive service with exact-owner validation and no alias following. Reject a malformed set; skip a name only for validated address absence. Build a sorted, deduplicated list of at most sixteen eligible IP endpoints. Excess limits fail instead of silently truncating. No address is taken from unsolicited additional-section glue.
4. An eligible authoritative endpoint is a globally reachable unicast address. Use a reviewed, explicit IPv4/IPv6 special-purpose classification policy, with a dated source and tests; normalize IPv4-mapped IPv6 before checking. Refuse private, loopback, link-local, unspecified, multicast, documentation and other special-purpose destinations. Reject the discovery result if it contains a prohibited address, rather than dropping that address and treating the remaining set as complete. Connect directly to the validated IP on port 53, never resolve its name again. Empty eligible set throws. Explicit recursive resolver addresses are the only exception to this destination policy.
5. Ask endpoints in deterministic order for IN/TXT at the exact original owner with RD=0. At most one UDP exchange and, only if TC is set on a validated matching response, one TCP exchange to the same endpoint per attempt. Budget each attempt to at most one second and the remaining overall deadline; TCP uses the remainder of that attempt. A timeout/network failure/invalid response can advance to another endpoint while budget remains; no background retry survives completion. Accept the first complete authoritative answer; consistency across all authorities is outside this slice.
6. Every exchange uses an unpredictable transaction ID and validates peer, ID, response bit, QUERY opcode, exactly one matching question/name/class/type and packet boundaries. TCP additionally validates its length frame; reject trailing, incomplete or oversized payloads. UDP truncation is never interpreted as an empty/partial TXT set. The final TCP response must have TC clear. Compression loops, invalid offsets, malformed RDATA and packet/record-count bounds throw for that attempt.
7. The final TXT response needs AA=1 and either NOERROR or NXDOMAIN. CNAME/DNAME at the queried owner or a claimed ancestor, referral, missing AA, mismatched TXT owner/class, and TXT material only in authority/additional sections cannot establish proof. NOERROR returns the exact-owner TXT RRset; a negative NOERROR/NXDOMAIN returns `[]` only with a valid enclosing SOA and no contradictory answer records. Otherwise it is unavailable. Decode each TXT record's character-string fragments as bytes joined in wire order, then losslessly into strings; preserve record boundaries and token bytes without trimming/case folding. Invalid text encoding is unavailable, not replacement characters. An unrelated valid TXT value is returned and the existing route decides it does not match.

Authority discovery is not DNSSEC validation. AA alone does not authenticate a server, and explicitly configured recursive discovery remains part of the trust boundary. No output may claim cryptographic authentication, resolver unanimity or a deployed ownership proof. This is the existing DNS-control method implemented with explicit limits.

## Resource ownership and failure

One lookup owns its sockets/timers and closes them on success, failure, cancellation and timeout. Bound packet size to 65,535 bytes and decoded records to 256 per packet; the codec must reject malformed offsets and cyclic compression before unbounded work. The adapter stores no cache or persistent state. Concurrent requests have distinct request state and cannot consume each other's replies. Faults are contextual errors without TXT content, addresses from client payloads, raw packet bytes or challenge digests in logs. The existing HTTP layer maps a lookup failure to 503 and unchanged persistence; valid absence maps through the existing mismatch outcome, not 503.

## Follow-ups and external prerequisites

The implementation may finish task 5.2's adapter/composition sub-slice with local protocol and mounted evidence. It does not close the whole task or WBS row until controlled real-domain and activated lifecycle acceptance are recorded. Tasks 5.3–5.5 still need automatic worker scheduling. SMTP, organization activation inventory, production browser-authority enablement, migrations/rollback acceptance and other organization tasks remain separate.

Operators must choose recursive resolver addresses, permit bounded UDP/TCP port 53 egress, deploy configuration, control a disposable domain and authorize an attended real challenge/rotation/failure exercise. No such input is needed to implement and locally prove this adapter. An incompatible DNS deployment (aliases, excessive NS/address counts, only private authoritative service) receives an explicit unavailable outcome until separately designed support exists.

## Protocol references

The query/answer validation and TXT record shape follow [RFC 1035, sections 3.3.14 and 4.1](https://www.rfc-editor.org/rfc/rfc1035.html). Zone NS authority and alias restrictions are described in [RFC 2181, sections 6 and 10](https://www.rfc-editor.org/rfc/rfc2181.html). These sources justify protocol requirements, not live acceptance or authenticated DNS claims.

Use the [IANA IPv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry/) and [IANA IPv6 special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry/) as dated classification inputs, together with multicast/unicast ranges. Their classification does not promise actual network reachability; that is observed by the bounded exchange.
