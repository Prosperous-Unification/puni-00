## Why

WBS070.14 can validate complete 2Gi source memory observations, but its local observer accepts an operator-selected runtime and filesystem roots. Consistent samples can therefore describe the wrong authority. F9 needs attributable runtime and source provenance before these diagnostics can support an installed acceptance exercise.

## What Changes

Add a separate acquisition path that derives runtime, node and source identity from protected installed source observation authority, authenticates every transport connection, and samples through retained process and directory references. Preserve the existing validator and local observer as explicitly non-authentic diagnostics. Order delivery as feasibility and native ownership, complete transport and sampler, then installed adversarial acceptance.

## Non-Goals

Enable automatic lab creation/deletion, change source limits, diagnose historical OOM, prove cold-start success, or grant complete F9 acceptance. This draft implements nothing and does not promote historical logs, fixture output or matching identity strings into authority.

## Constraints

Baseline is release candidate `0aab48a2415d51e461abaf987c95ef576a194736` (#546), pending merge. No caller-supplied executable, endpoint, PID, namespace, roots, digest or receipt can authorize the authenticated path. Required identity, installation, capability or observation failures refuse evidence. Native one-shot relay is a conditional candidate until ownership, authenticated CRI transport and lifetime proofs pass; its tiny-message spike is insufficient. Bun and Nx remain the entry points for packaging and checks. No live-host changes belong to this planning PR.
